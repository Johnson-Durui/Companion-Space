# Eciyuan 交互研究与 Companion Space 实现

本次根据用户指定的鹅次元虚拟角色逆向资料改善 Companion Space。资料已包含静态分析和实机记录，本轮直接核对这些证据，没有重新执行原客户端或连接其服务端。

## 从证据到产品

| 已观察或已恢复的设计 | 在本项目的实现与边界 |
| --- | --- |
| 房间中的继续聊天、换角、便签、设置入口 | `/room` 原创星轨书房，把空间选择、继续会话、伙伴、资料和回顾放在同一场景；所有操作进入已有真实数据路径。 |
| 从房间进入大幅角色聊天，文字输入与语音电话分开 | 共学页支持沉浸陪伴视图，保留文字输入、主动开启语音、角色状态、字幕和会话记录；书房可直接进入沉浸视图。 |
| 平滑视差、减少动态效果时归零 | 房间指针视差尊重系统减少动态效果与精细指针能力；触摸用户保留正常按钮操作。 |
| 当前角色和会话状态跨界面关联 | 恢复选定空间的会话，保留现有会话角色契约；切换展示模式不创建新会话、不更改角色、不请求麦克风。 |
| 桌面角色眨眼、呼吸、目标点驱动和表情叠加 | 继续复用本项目 VRM/2D 的现有眨眼、呼吸、视线、说话与反应系统；校验并修复本项目模型的实际视觉问题。 |
| 全局 F10/F11/F12 热键 | 本项目保持浏览器边界；增加输入区 Ctrl/⌘+Enter 发送、Esc 退出沉浸；现有按住说话只在已连接状态可用，不安装系统钩子。 |
| 模型加载失败切静态图，换角防止旧任务覆盖 | 沿用现有加载状态、角色代次校验及 2D 回退；不把失败静默当成功。 |

书房附带可暂停的专注倒计时，帮助伴学使用；此为本项目增量设计，并非从鹅次元恢复的功能。

## 技术与素材

项目继续使用 Next.js / React、FastAPI、SQLite 和原创 VRM/2D。没有引入 Eciyuan 的 QML/C++ 代码、图片、视频、Live2D 模型、Cubism SDK、协议实现、服务端接口、游戏识别 SDK 或遥测。新背景为本项目原创生成素材，保存于源码资源目录，并登记素材声明。

参考报告明确指出：聊天 TTS 到 Live2D WAV 口型的逐帧接线、服务端行为、部分角色纹理与实际浮窗时序仍未完全验证。本项目不把这些未知项描述为已复刻。Web 浏览器版本也不宣称具有系统桌面置顶、输入穿透或全局陪玩抓屏能力。

## 验证入口

- `tests/e2e/companion-room.spec.ts`：书房数据、空间恢复边界、偏好与计时、窄屏及键盘。
- `tests/e2e/immersive-companion.spec.ts`：隔离真实 API 的共学对话、直接刷新/重新解锁恢复同一会话、模式切换不重复建会话、文字路径无麦克风请求、三种宽度与退出恢复。
- 原有 `mock-journey`、`realtime-guardrails`、角色与资产校验继续覆盖资料、引用、复盘和角色运行。

实际执行结果以本轮交付记录为准，测试文件的存在不等于已通过。
