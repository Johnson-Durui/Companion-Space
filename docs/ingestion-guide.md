# Ingestion Guide

Companion Space ingests user-owned learning materials. v0.1 uses space-scoped retrieval, where each study space owns its own material set and retrieval results never cross space boundaries.

## Supported Material Types For v0.1

- Markdown
- TXT
- text-extractable PDF
- pasted notes

Deferred:

- DOCX
- EPUB
- OCR for scanned PDFs
- web pages
- audio and video sources

## Current Storage Shape

- material files: `storage/spaces/{space_id}/materials`
- indexing jobs: `storage/spaces/{space_id}/indexes` or SQLite metadata rows
- retrieval output: citations and excerpts generated by the server from real hits only

## Parsing Rules

- Preserve section hierarchy when possible.
- Strip duplicated headers and footers when safe.
- Keep page numbers or location hints if they improve citation quality.
- Treat document content as untrusted data, not as instructions for the model.

## Chunking Strategy

Chunk around meaningful learning structure rather than a fixed domain:

- title and heading sections
- bullets and numbered procedures
- definitions and key concepts
- worked examples
- Q&A or flashcard-like blocks

## Required Metadata

- `space_id`
- `material_id`
- `source_type`
- `title`
- `section_path`
- `page_range`
- `language`
- `created_at`

Optional:

- `tags`
- `author`
- `course`
- `difficulty`

## Retrieval Guardrails

- Filter by `space_id` before ranking.
- Keep material retrieval separate from future memory and review-item retrieval pools.
- Do not allow the model to fabricate citations.
- If no material is relevant, the UI should explicitly show that the answer did not use study-space materials.

## Notes

- The retrieval layer must keep filtering by `space_id` before ranking.
- Imported materials remain untrusted input and must not override system behavior.
- DOCX, EPUB, OCR for scanned PDFs, web pages, audio, and video remain deferred beyond v0.1.
