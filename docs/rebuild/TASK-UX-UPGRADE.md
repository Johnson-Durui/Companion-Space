## 二、通用纪律

1. **开工核对**：分支应为 `rebuild/tutor`。不推送、不改写历史、不切换分支；禁用的 git 命令见 `AGENTS.md`。
2. **门禁（每个停止点与每个内部检查点必过）**
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/gate.ps1 -Frontend -Contract
   npm run test:e2e
   ```
   门禁脚本不含端到端用例，界面工作必须另外跑 `npm run test:e2e`。**端到端用例跑的是已构建的前端**（`apps/web/dist`）：改了前端之后先重新构建再跑，否则测到的是旧界面。本机没有安装 Playwright 自带浏览器时，设置环境变量 `PLAYWRIGHT_CHANNEL` 为 `msedge` 或 `chrome`。接口有变化先 `npm run generate:api` 并提交生成物。
3. **范围**：只改界面、样式、前端状态，以及体验规格 §8 的 B1–B15。体验规格 §10 的不做清单与本文件附录 B 同样适用。
4. **测试纪律**：先让新测试失败再让它通过；断言行为与不变量，不断言文案、常量、截图像素。端到端用例按角色与可访问名（通过文案键取）或 `data-testid` 定位，**不按样式类名定位**；状态属性可以用于断言（现有的 `data-pose`、`data-action`、`data-clip`、`data-state` 保留；`data-phase` 在 U2a 新增）。要改结构，先改定位方式并保持用例通过，再改结构；涉及结构大改的用例在对应里程碑**重写**而不是修补。测试夹具需要新场景时加在 `services/api/tests/fakes/`，并登记到 `services/api/tests/e2e_server.py` 的场景清单。
5. **体验不变量**：清单见体验规格 §9。I4 是前端单测（随门禁跑）；其余在 `tests/e2e/ux-invariants.spec.ts`。每个停止点，本里程碑及之前的不变量都必须通过。
6. **截图巡览**：每个停止点先**更新巡览步骤**（使其覆盖本里程碑新增与改动的界面和状态），再运行，把所有主要界面与状态（桌面 1440×900 与手机 390×844）输出到 `docs/rebuild/review/U<n>/`（已被忽略，不提交）。巡览除常规夹具外，必须包含一组**压力内容**场景（加在测试夹具里）：30 字以上的课程名与课题、三行题干加 6 个长选项、含长公式与 20 行以上的白板、60 个以上知识点的地图、3 门课的今天页、空课程——短内容永远好看，问题出在长内容上。巡览步骤失败的数量如实写进 `PROGRESS.md`。基线在 `docs/rebuild/review/U-baseline/`，目标效果图在 `docs/rebuild/reference/mockups/`。截图只用于人工评审，不作为断言。
7. **一屏的完成定义**：每个停止点，对本里程碑动过的每一屏逐条核对设计系统规格 §12，把没达到的条目如实写进 `PROGRESS.md`。
8. **依赖与许可**：引入或升级前查官方文档与许可文件；版本锁定；用途、许可、替代方案写入 `DECISIONS.md`。字体按 `AGENTS.md`"素材与许可"处理（设计系统规格 §2.5），不适用代码依赖的许可名单。设计系统规格 §4 列出了允许的选择与明确不引入的东西。
9. **不留两套**：旧样式在 U1 整体进入 `legacy` 层（设计系统规格 §3.1）；改到的页面在同一批提交里删掉对应的旧规则；不新增页面级全局类；**禁止用 `!important` 或提高选择器权重对抗旧样式**。
10. **降级与错误可见**：任何回退都要让学生看到原因和修复入口；不吞异常；不编造进度或数据。
11. **模考取值的例外**：模考计划项的真实取值是字符串 `mock`，与防空壳脚本的禁用词相同。前端把对计划项类型的判断集中在一个模块里（导出"是不是新课 / 练习 / 模考"的判断与类型文案键），后端集中在已登记的排课模块导出的常量；其余文件只引用它们。确实需要直接写到该取值的新文件，逐个登记进 `scripts/no_fakes_allowlist.txt`（路径 + 理由），文件移动或删除时同步更新名单。不得为绕过检查而改用"不是课就是模考"这类反向判断。
12. **验收准备（每个停止点必做，写进 `PROGRESS.md` 本里程碑小节最前面的"怎么验收"）**：
    - 最后一次改动后重新构建前端，确认所有者启动后看到的是新界面（启动脚本只在没有构建产物时才构建）。
    - 给出可以直接照做的启动方式：日常数据双击 `start.bat`；需要全新数据时运行 `scripts/start-review.ps1`（U0 新增：把数据目录指到一个新的临时目录后启动，不触碰真实数据；脚本只含 ASCII 字符）。
    - 逐条标注验收清单里哪些需要真实的 AI 服务、哪些到不了的状态改看 `review/U<n>/` 里的哪张截图。
13. **内部检查点**：U1、U2a、U2b、U3 体量大，按各节给出的分段推进。每段结束门禁全绿并在 `PROGRESS.md` 记一行（不需要所有者验收）；会话在检查点之外结束前必须先提交并写明做到哪一条。
14. **汇报模板**（写入 `PROGRESS.md` 的"体验重塑 U<n>"小节）：先写"怎么验收"，再写**待完成与待验证**，然后是**已落地**与**本地验证**。状态沿用 `AGENTS.md` 的四种：`进行中` / `代码完成（自动化通过）` / `真实模型实测通过` / `所有者验收通过`。不创建其他过程文书。

**每个里程碑的所有者验收清单末尾都追加"观感五问"，任何一条答"否"即不通过：**

- A. 任选本里程碑的三屏，和 `U-baseline` 里的同一屏并排看：新的一屏是不是一眼就知道该点哪里？
- B. 有没有文字被截断、挤成一团、溢出卡片，或者两个东西没对齐？（重点看压力内容那组截图）
- C. 有没有哪里还是一行灰字、浏览器自带的控件或英文？
- D. 每个按钮点下去是不是立刻有反应？有没有哪一步让你等着却不知道在等什么？
- E. 这一屏如果截图发给朋友，你会不会不好意思？
