## 1. 结论

**引擎已经有了，缺的是"产品"这一层。** 资料分析、学习者模型、计划、课堂引擎、语音、纯视频老师都已经做出来；但界面是把这些能力按开发顺序挂到页面上，所以它能跑通，却像演示品。

"像 demo"不是因为不够花哨，而是六件具体的事（§3）。这份计划做的是：**把已有的能力，按一个学生真实的学习过程重新组织、重新呈现**——打开就是老师，每一屏只有一个下一步，上课像一通视频电话，学到的东西看得见。

范围要说清楚：这个阶段**不改教学内容怎么生成、怎么判分**。新增的是"把已有能力接成一条线"所需的界面功能（候课、连接向导、对话记录、课程改名与删除等），加上十五项后端配合；其中大多数只是把已经算出来的数据交给界面，有两项（摸底的跳过逻辑、开课时的备课方式）会改变现有接口的行为，需要重点回归。

按 U0 → U1 → U2a → U2b → U3 → U4 → U5 → U6 → U7 推进，共九个停止点，每个结束都是可用的产品，都停下来等你验收。

## 3. 为什么像 demo：六个根因

**R1 界面是"功能面板"，不是"旅程"。**
课程页从上到下是：学习设置（折叠）→ 导入 → 分析 → 地图，无论这门课是刚建好还是学了一半，永远是这五块、这个顺序。你最看重的"了解学生 → 个性化计划"被放在一个默认收起、名字叫"学习设置"的面板里，排在两张表单之后；而页面上最显眼的按钮（地图里的"开始或继续这节课"）可以绕过它直接开课。没有首页，回来的学生看到的是课程管理列表。从建课到第一节课要填约 25–30 个表单字段、点 3 个独立的保存按钮，分布在 6 个页面，页面之间没有"下一步"。

**R2 老师只活在一个路由里。**
产品的灵魂是"你喜欢的角色"，但 TA 只出现在选老师页和课堂里。新用户点的第一个主按钮"看一节示例课"，进去是一个带"播放"按钮的纯文字回放——**没有老师**。"AI 提问了解你"是一个文本框加三个按钮，朗读用的是浏览器合成音而不是老师的声音。加载、空状态、等待全是一行灰字。六位老师换谁，界面都是同一种墨绿；其中两位（初棠与澜音）用的还是同一个声音。

**R3 课堂是一张会滚动的网页，不是一通电话。**
老师提问时页面高 3110 像素而视口只有 900：题目在白板最下面，输入框和麦克风按钮在更下面，学生要来回滚动。网站顶部的导航在课堂里依然常驻。手机上 9:16 的竖屏老师被裁成一条只露出头顶的横条。此外有四处实测的行为错误：

1. 答错、点"没听懂"、点"给点提示"之后，老师播放的都是**点赞**片段。
2. 显示"在想"时老师还在播放张嘴讲话的片段。
3. 第一次进课堂、还没开始，状态写着"已暂停"。
4. 判定出来、老师还在讲评时，状态又变回"等你回答"。

另外，点"开始上课"后如果这节课还没备好，学生要对着一个按钮干等约一分钟。

**R4 没有"手感层"。**
全站可复用的组件只有 3 个（加载文字、错误条、错误边界）；有二十多个系统外观的下拉框、5 处浏览器自带的确认弹窗、系统灰色的音频播放条；没有一个图标，品牌标志和播放键都是文字符号，浏览器标签页没有图标。样式里声明的三款字体没有随应用一起提供——**你的电脑上恰好装了思源黑体和思源宋体，所以你看到的标题是正常的；没装这些字体的普通 Windows 电脑上，所有大标题会退回系统自带的宋体**（模拟截图见 `docs/rebuild/review/U-baseline/00-other-machines-*.png`）。也就是说，别人看到的比你看到的更粗糙。按钮没有按下的反馈；保存成功是一行不会消失的小字；页面之间硬切。答题对错——学习产品里情绪最强的一刻——是白板底部的一行灰色小字；课后小结只有一句话和一个"回放"按钮。

**R5 是系统在说话，不是老师或产品在说话。**
"估算并开始分析""预计使用约 N token""模型角色：独立复核 / 向量检索""本地 GPU 实时驱动（Sidecar）""云端实时数字人护栏（Tier 3 预留）""Render failed"。一级导航的第四项"试聊"其实是连通性自检工具。设置页是一条 3600 像素长的工程配置长卷。

**R6 个性化与进步看不见。**
引擎做了、界面没显示的东西：计划为什么这样排、这一版和上一版差在哪、哪些内容因为时间不够被放弃了；下课后计划自动重排了，界面一个字没说；课上你说"没听懂"，老师确实换了讲法或回头补了前面的知识点，白板上没有任何标记；复习题答完直接换下一张，不告诉你对错、正确答案和下次什么时候再见（这些后端都返回了，被前端丢掉）；进度页是一列灰色的系统进度条。"它在为我调整"是这个产品最核心的卖点，现在用户感知不到。

**做得好、要保留的**：课堂状态由事件流重建（刷新、重连都能恢复）；低延迟的预览通路与 150 毫秒的即时反应；语音预填后先确认再判分；降级链路可见；白板的纸面质感与书写动效；可访问性的底子（焦点环、键盘、读屏标注）；数据诚实（掌握度只来自作答证据）；文案集中在一个文件里。这些是地基，重做体验时都不动。

## 4. 设计逻辑：把闭环重新走一遍

你的设想是一条闭环。每个时刻学生心里有一个问题，界面要回答它，并且只给一个下一步。

| 时刻 | 学生心里的问题 | 现在 | 重做之后 |
| --- | --- | --- | --- |
| 相遇 | 谁来教我？ | 一张详情卡 + 44 像素的小头像条；所有老师试听同一句话 | 六张会动的大卡片；选中后老师做自我介绍，说 TA 自己的台词，用 TA 自己的声音 |
| 交资料 | 我的教材给谁？ | 课程长页中间的一个面板；传完要自己再点"估算并开始分析" | 一整屏的投放区；"交给老师"之后自动开始读 |
| 被读懂 | 它看懂了吗？ | 10 个流水线阶段名 + token 计数 | 老师口吻的进度、大致还要多久、读完后的结果卡 |
| 被了解 | 它知道我的情况吗？ | 折叠面板里的两张表单 + 一个文本框 | 老师面对面问几个问题（有画面、有声音；考试日期直接用日期选择器，每周哪几天直接点），问过的不再问；然后一题一屏的摸底 |
| 拿到计划 | 该怎么学，为什么？ | 同一个折叠面板底部的一列条目，每条一句百分比 | 排到考试日的计划：每节都说得出为什么；时间不够放弃了什么也明说 |
| 上课 | 听得懂吗，卡住怎么办？ | 一张长网页 | 一通视频电话：老师、白板、固定的控制条；题目永远在眼前；换讲法、回头补，白板上都写出来 |
| 回来 | 今天学什么，进步了吗？ | 课程管理列表 | "今天"页：老师问候、今天的课、到期复习、离考试几天、保住了多少分 |

三个推论，决定了整个方案的取舍：

- **个性化必须是主路径。** "直接学某个知识点"保留，但降为次级入口。
- **"它在为我调整"要说出来。** 计划变了、掌握度变了、课上换了讲法，都有一句由数据拼出来的话。
- **老师是界面的主语。** 能让老师说的，就不让系统说。

闭环也有尽头：课都上完了、考试日过了，界面要有交代（总结 + 继续复习 / 补上暂缓的内容 / 设新的考试日期），而不是永远挂着"今天的课上完了"。

## 5. 做完是什么样

**第一次打开**：第一屏是六位在轻轻动的老师。点一位，TA 打招呼、讲一句自己的台词。选定后只问你一件事——怎么称呼你，然后连接 AI 服务：选一家、照着指引去拿密钥、粘贴，它自己测试并告诉你"可以上课了"。不想马上配置，可以先看一节几分钟的示例课，里面有老师，也有她的声音。

**准备一门课**：把教材和真题拖进去，点"交给老师"。老师开始读，你不用等——她一边读，一边问你几个问题。读完后做几道摸底题，然后计划出现：离考试 23 天，每周学 4 天，一共 18 节课；每节都能点开看"为什么排在这里"。

**上课**：点"开始上课"，立刻进入候课——老师在备课，你可以先热身几张复习卡。接通后没有网站导航，整个屏幕就是课堂：左边是老师的竖屏画面，右边是白板，下面一排控制按钮，页面永远不滚动。老师在听、在想、在讲，看她就知道。她提问时题目从白板下方滑出来；你答对，选项打勾，她点赞；你答错，她安抚你，然后白板上出现一行"换个讲法再讲一遍"。

**下课**：她道别，然后是课后小结——今天讲了几个要点、你答对了几道、有几处换了讲法、哪几个知识点的掌握变了、计划因此怎么调了、下一节是什么。

**每天回来**：打开就是"今天"。她问候你，告诉你今天有一节课和六张复习卡，一个按钮开始。

## 6. 设计方向

**两种模式。** 日常页面是"书桌"：浅色、干净、留白，老师是画面里最鲜艳的东西。课堂是"课堂"：接近黑的深色舞台，老师的画面和一张柔和的纸面白板。

**老师决定气质。** 每位老师有一组人工指定的主题色（已给出起点取值，对比度和彼此的区分度都核过；观感由你在 U1 的组件陈列页上确认）。选了谁，全应用的主按钮、高亮，课堂里的光晕和当前行，都换成 TA 的颜色。

**字、图标、组件一次到位。** 不再用宋体标题；西文与数字用一款现代可变字体，中文默认打包思源黑体（开源、可随仓库分发、约 4.5 MB）——**U1 验收时你在自己的显示器上对比"打包字体 / 系统字体"，二选一**；一套统一的描边图标；一个组件库，替换掉所有系统外观的控件和浏览器弹窗。

**手感有规矩。** 任何点击 100 毫秒内有回应；每一段等待都有名字（没有真实进度数据时不显示假的百分比）；只动位移和透明度，一般动画不超过 300 毫秒；能撤销就不弹确认；错误说人话并给出下一步。这些规矩写成了带数字的规范和一份 25 条的"一屏完成定义"。

关键取舍：

| 决定 | 理由 |
| --- | --- |
| 真正用上已安装的 Tailwind v4（token + 工具类 + 组件），不再写页面级全局样式；旧样式先整体收进一个"遗留层"，逐页清空 | 现在它只被当作样式重置；174 个类名里约 140 个只用一次，一致性无从保证。不先把旧样式分层，它会压过所有新组件 |
| 无样式组件库选 Base UI，图标选 lucide，不引入动效库、图表库 | 许可合规、在维护、一个库覆盖对话框到抽屉；动效用 CSS 就够 |
| 课堂占满一屏，白板是唯一的滚动区，题目从白板流里拿出来做成托盘 | 这是"网页"与"通话"的分界线 |
| 课堂状态改为一个显式的相位状态机，输入与每个相位的出口都写明 | 四处状态错误里三处源于课堂里散落的条件判断，一处源于形象包里"姿态对应哪个片段"的表；状态机可以单测，不会再把学生锁死在"等判定" |
| "选中"用描边，"答对 / 答错"用底色加图标 | 老师的主题色可能和"答对"的绿色相近，不能靠颜色区分 |
| 开课不再让请求挂着等备课，改为立刻进入候课界面 | 一分钟的等待要么被看见，要么被用来热身 |
| 访谈的每个问题都配点选控件（日期选择器、星期多选等），不只是文本框 | 排计划必须拿到考试日期和每周时间；只靠模型从一句话里抽，抽不出来计划就没有日期。点选也让没连 AI 服务时照样能完成访谈 |
| 课程页拆成"今日 / 计划 / 地图 / 复习 / 进度 / 记录 / 资料"，准备过程做成五步流程 | 把"功能面板"变成"旅程" |
| 组件只在第一次用到它的里程碑里做；U2 拆成"一屏课堂"和"候课与韧性"两个停止点 | 避免做一堆暂时没人用的东西；让你最在意的课堂尽早看到 |
| 体验用可自动检查的不变量守住（十六条），而不是靠截图比对 | 例如"课堂任何相位页面高度等于视口高度""答错时不播放表扬片段" |

## 7. 路线图

| 停止点 | 一句话 | 做完你会看到 | 规模 |
| --- | --- | --- | --- |
| **U0 止血与准备** | 先把今天就错的地方修掉 | 答错不再点赞；摸底不会被悄悄跳过；没有英文残留；浏览器标签页有图标。外观基本不变 | 小 |
| **U1 设计系统地基** | 全站换肤，组件库就位 | 新字体、新配色、图标、应用内对话框、会消失的提示、按压手感；换老师换颜色。**你要在这里定字体、看版式样板** | 大 |
| **U2a 一屏课堂** | 上课像一通视频电话 | 一屏的课堂、题目托盘、控制坞、状态一眼可辨、"换个讲法"看得见、文字上课也完整 | 大 |
| **U2b 候课与韧性** | 进门有仪式，断线不是死胡同 | 候课与备课等待、接通过渡、重连、示例课与回放里有老师 | 中 |
| **U3 旅程与信息架构** | 产品有了主线 | "今天"页、五步准备流程、连接向导、课程中枢、有内容的课后小结 | 大 |
| **U4 老师在场** | 选老师是一次相遇 | 老师画廊与自我介绍、六种不同的声音；老师出现在顶栏、今天页、空状态里 | 中 |
| **U5 学习闭环可视化** | 每一页用图回答一个问题 | 掌握度方格图、考点榜、计划变化说明、复习的答后反馈、练习结果页 | 中到大 |
| **U6 课堂深化与手机端** | 白板有"在讲"的感觉 | 逐行书写与指向、白板翻页、对话记录、提示音、手机上的通话布局 | 中到大 |
| **U7 设置重排与收尾** | 设置像给学生用的，对外材料更新 | 分区的设置页、没有术语的默认界面、新的 README 截图 | 中 |

顺序的理由：先修错（U0）→ 地基（U1，之后每一页都靠它）→ 最核心也最独立的课堂（U2a、U2b）→ 主线（U3，回应"设计逻辑"）→ 其余按依赖关系排。

要有一个合理预期：U0 外观不变，U1 是旧版式换皮——第一次明显的"变好"在 **U2a**，那时上课这一段就和现在判若两样；进门、选老师、课程页要到 U3、U4 才变。

## 8. 需要你做的

- **每个停止点**：按任务单里那一节的验收清单亲手点一遍（都是"点哪里、应该看到什么"，不需要看代码），并回答清单末尾的"观感五问"——它专门用来抓"功能都在，但还是糙"。Codex 会在进度文件里写清楚怎么启动、怎么得到一份全新的数据、哪些条目需要真实的 AI 服务。
- **三次必做的评审**：U1（基调）、U2a（课堂）、U3（主线）结束时，把 `docs/rebuild/review/U<n>/` 的截图拿回来给我看，我对照规格和目标效果图逐屏挑问题。这三处返工最贵。
- **十一个默认决定**（任务单附录 A）：例如"试聊"并入设置、切走标签页半分钟内回来自动接着上、提示音默认开、示例课用老师的声音。我都替你选了，不同意的在对应里程碑开工前改掉即可。其中两件需要你看实物定：字体（U1）、课堂纸面的亮度（U2a）。
- **角色的文字与声音**：六位老师的一词气质与问候语，我给了建议值，这是你的创作，欢迎改；U4 要试听并定下六位老师各自的声音。
- **验收条件**：一个可用的 AI 服务密钥、一副耳机和麦克风；U6 需要一部手机或把浏览器调成手机尺寸。

## 9. 风险与诚实的话

| 风险 | 应对 |
| --- | --- |
| 界面好看了，但教得不对 | 这个阶段不改教学引擎。M2、M4、M5 的真实模型验收仍然挂着，建议 U2a 之后用你自己的资料完整上一节课。**界面解决不了教学质量。** |
| 范围大，代理跑偏或做成"半新半旧" | 九个停止点，大的里程碑内部还有检查点；U1 先整体换肤，之后每页重做时同批删掉旧样式，不允许两套并存 |
| 结构一改，现有的端到端用例大面积变红 | U0 先把用例从"按样式类名定位"改成"按角色与名称定位"；涉及结构大改的用例在对应里程碑重写而不是修补 |
| 代理的审美不稳定 | 颜色、字号、间距、动效都给了具体数值；三张目标效果图；U1 的版式样板关口；每个停止点出全量截图（含一组专门的长内容压力场景）；三次必做的评审 |
| 两处后端行为变更（摸底的跳过逻辑、开课改为先候课后备课） | 各自先写会失败的后端测试；U0 与 U2b 的验收专门覆盖 |
| 老师的声音默认依赖在线语音合成 | 断网或该服务不可用时老师只有画面和文字，界面明确提示并保留文字；离线语音不在本阶段 |
| 读资料与访谈同时请求模型，免费额度可能被限速 | 访谈回退到点选控件（不需要模型）；读资料自动重试并在进度里说明 |
| 本机服务重启后课堂能不能接着上，还没核实 | U2b 的任务里先核实再决定呈现方式，结论写进决定记录 |
| 依赖版本与我的调研有出入 | 规格里的版本号都标了调研日期，并要求动手前按仓库约定重新核对 |
| 再次出现"看起来完成" | 十六条可自动检查的体验不变量 + "观感五问" + 所有者亲手验收；汇报先写没做完的 |
