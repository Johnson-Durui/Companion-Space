## 1. 使命

> 让每个"课上听不懂、又请不起一对一"的学生，都能把自己的资料交给一位自己喜欢的老师，听她/他用适合自己的方式，一遍一遍讲到懂为止——并且把时间花在真正会考的地方。

**产品一句话**：把你的教材、课件和真题，变成你喜欢的角色给你上的一对一课。

三个痛点对应三个承诺：

| 大课的问题 | 本产品的承诺 | 落到产品上 |
| --- | --- | --- |
| 节奏统一，跟不上没人等 | 老师只教你一个人，按你的掌握情况推进 | 学习者模型 + 掌握度驱动的课堂 + 不懂就换讲法 |
| 讨厌老师的风格却换不了 | 老师是谁、怎么讲，你说了算 | 可选角色（形象+声音+人设）× 可随时切换的讲课风格 |
| 老师不看考情，力气花在不考的地方 | 每节课都说得出"为什么先学它" | 真题分析 → 知识点考频/分值/趋势 → 计划按提分价值排序 |

定位修正：旧文档把产品定义为"搭子而非老师"，并据此让提示词回避教学。**新定位：角色就是你的专属老师（可以是学姐、同桌、严师等任何你喜欢的关系感），陪伴感来自她/他真的在教你、记得你、对你有耐心。**

## 2. 现状诊断（2026-11-16 实测与逐文件审计）

所有者的判断"效果和预想差之甚远"是准确的。原因不是功能少，而是**核心是空的**：

| # | 事实 | 证据 |
| --- | --- | --- |
| D1 | "互动课堂"是写死的五段式剧本：测验正确答案恒为 `b`；闪卡与纠错话术是固定模板；只有"二分查找"有真正的推演 | `services/api/app/services/pedagogical_orchestrator.py`、`classroom_curriculum.py`。实测主题"函数的极限"：测验题是"哪种学习顺序与当前板书一致"，答错反馈是"这个选项会破坏边界不变量"，闪卡是"函数的极限 的核心不变量是什么" |
| D2 | 自由对话是"带人设的资料问答"，提示词明确反对教学 | `libs/prompts/system_core.md`："不自称老师，也不把用户当成学生训导"；`companion_rules.md`："不以说教、打分或训导作为默认互动方式"；板书每轮最多 1 条且整段生成后才出现 |
| D3 | 不存在"AI 自动分析资料"：导入只做切块和索引 | 仅支持 md/txt/文字版 PDF；无 OCR、无 PPT/Word/图片；单块超过 1400 字的内容被截断丢弃；中文检索基本只能命中块首；配置宣称的 BGE 向量与重排从未运行 |
| D4 | 没有学习者模型，也就谈不上个性化 | 数据库没有知识点、掌握度、画像、计划、作答记录等任何表；没有访谈与诊断 |
| D5 | 没有学习计划，没有考情分析 | 全仓库无相关代码 |
| D6 | 语音不是"边想边说"：整段回复生成完才合成一次；口型与语音内容无关 | `api/routes/realtime.py` 的回合流程；`packages/avatar-engine/src/viseme.ts` 是按时钟循环的 5 个口型。零配置（Mock）下转写是固定句、回复是固定句、朗读靠浏览器 |
| D7 | 6 个"原创 3D 形象"是脚本用圆柱/球体/方块拼出的人偶；手臂被代码强制张开；动作文件是手敲的 5 个关键帧 | `scripts/blender/build_original_companions.py`、`scripts/generate-original-vrm.mjs`、`vrm-stage.tsx` 中把上臂每帧固定为 1.08 弧度。真正好看的是 4 个示例 VRM 和 6 张 2D 立绘 |
| D8 | 上手门槛高：第一屏要求先设"保险箱主密码"，每次重启都要再输；带自己的资料走到开讲需要 12 步以上、11 个概念 | 实测首屏"先打开本地保险箱"。开发数据库里 14 个空间、0 份资料——开发过程中都没有被真正用来学过东西 |
| D9 | 工程量花在了外围：约 2 万行测试里相当一部分在钉常量；文档约 60% 是发布证据；手机壳、设备配对、Live2D 桥、成人模式等支线先于核心完成 | 审计统计；v2 重构（+1,480 / −23,451 行，含大量未跟踪文件）至今没有任何提交 |

**根因（重塑必须针对的四件事）**：

1. **定位回避了"教"**——"不是老师"的设定直接写进了提示词和产品形态。
2. **验收建立在"无密钥的 Mock 流程能走通"上**——于是写死的演示逻辑就能通过全部验收，真实模型下的教学质量从未被检验。
3. **以数量自证**——测试条数、证据文档、截图代替了"一个学生真的学会了一个知识点"。
4. **核心难题只被命名、没被设计**——"教学编排器""因材施教"有名字，没有学习者模型、没有教学策略、没有可靠出题与判分。

真实可用、值得保留的底座：供应商适配与密钥加密、会话状态机与流式事件、SQLite 迁移器、音频采集与播放队列、WebSocket 票据鉴权、VRM 加载与相机取景、角色 CRUD 与 VRM 导入校验。详见 `spec/architecture-and-data.md` §9。

## 3. 目标体验

### 3.1 第一次使用（目标：10 分钟内上到第一节课）

1. 双击 `start.bat`，浏览器自动打开。**没有密码、没有保险箱页面。**
2. 欢迎页：选一位老师（卡片上有预览和试听）。可以先点"看一节示例课"（不需要任何密钥，回放预生成的真实课堂）。
3. 连接模型：从预设里选一家（列出免费/低价选项与获取密钥的链接）→ 粘贴 Key → 一键测试（真的对话一句、识别一张图）。语音默认零配置可用。
4. 新建课程：把教材、课件、笔记、真题一起拖进来（自动识别每个文件的角色，可改）。
5. 分析进度页：实时看到"正在读第 3 章 · 已发现 42 个知识点 · 已分析 2/5 套真题"。
6. 课程地图：章节 → 知识点，按考频/分值着色；点开能看到出处页码和对应真题。
7. 老师来认识你：3 分钟对话式访谈（目标、考试日期、每周时间、现在的水平、喜欢的讲法）+ 6–12 题的起点诊断（随时可点"不会"）。
8. 你的计划：到考试日为止的每一节课，每节都写着"为什么先学它"；时间不够时明说取舍。
9. 开始第一节课。

### 3.2 一节课里发生什么（核心体验）

- 左边是老师（3D，半身，有口型、眼神和手势），右边是白板，底部是输入条（按住说话/打字 + "没听懂 / 举个例子 / 讲慢点 / 我会了"）。
- **老师主导**：先说今天学什么、为什么值得学；边写板书边讲，一次只讲一个要点；每个要点后必有一个小问题。
- **答对**：具体指出你哪一步想对了，继续。**答错**：不直接给答案——先点拨方向，再缩小范围，第三次才示范完整解法，然后换一道同类题再试。
- **不想被吊着**：随时可以点"给点提示"或"看答案"；看过答案的题不算你会了，老师会再出一道同类题确认。
- **没听懂**：换一种讲法（直觉、具体例子、图像、严格表述、类比、对比常见错误），永不重复原话；可以点白板上"从这一行开始没跟上"；连续不懂时回头补你缺的前置知识。
- **随时打断，也可以离开**：你一开口或一点击，老师立刻停下；你没回应时老师只提醒一次，然后暂停等你——不回应不会被记成"不会"。
- **随时换风格**：循循善诱 / 直截了当 / 生活类比 / 应试提分 / 严谨推导，课堂上一句话就能切换。
- **下课**：如实的小结（学会了什么、哪里还不稳）、掌握度变化、自动生成的复习卡和错题。

### 3.3 以后每天回来

首页只有三样：**今天的课**（一键继续）、**到期复习**（上课前 5 分钟热身）、**离考试还有几天 / 已保住多少分值**。老师记得你上次卡在哪里。

## 4. 产品原则（所有设计与实现的裁决依据）

1. **老师主导，学生随时可打断。** 不是学生点"下一步"的幻灯片，也不是等学生提问的聊天框。
2. **策略由代码决定，表达由模型生成。** 什么时候讲、问、提示、回补、放行，由可测试的规则决定；怎么说得像这个角色，由模型负责。
3. **先解后教。** 没有经过独立复核答案的题，不能用来判分、诊断或更新掌握度。
4. **掌握度只认证据。** "已掌握"永远来自作答记录的计算，不来自模型的口头判断。
5. **不懂就换讲法。** 同一要点的每次重讲必须使用不同的讲法并记录在案。
6. **时间花在考点上。** 每节课都能回答"为什么先学它"；时间不够要明说放弃了什么。
7. **诚实。** 资料里没有就说没有；没验证就写"未验证"；失败要可见。任何报告先写"还不行的地方"。
8. **十分钟见老师。** 零密码、一条命令、模型预设、默认可用的语音。
9. **角色是老师这个"人"，不是皮肤；但准确永远优先于可爱。**
10. **少而真。** 宁可少一个功能，不要一个假功能。演示能力靠"预生成的真实内容回放"，不靠产品代码里的假逻辑。

## 5. 总体方案

**保留底座，重建产品。**（处置表见 `spec/architecture-and-data.md` §9）

关键设计决定：

| 决定 | 理由 |
| --- | --- |
| 教学 = 备课（慢模型、可复核）+ 导演（纯代码策略表）+ 表达（快模型流式） | 把"教得对不对"变成可单测的规则，把"说得像不像"交给模型；题目答案在备课阶段复核，课堂上不临场编题 |
| 模型输出用"标签流"而不是 JSON | 板书充满 LaTeX，JSON 转义会被便宜模型写坏；标签流可增量解析，天然支持"说一句、写一笔" |
| 说话与板书走同一条有序时间线 | 实现"边写边讲"和干净的打断语义（生成编号 + 已听到位置） |
| 掌握度用透明公式（BKT 式更新 + FSRS 复习） | 单个学习者数据稀疏，复杂模型没有意义；透明公式可解释、可测试 |
| 计划用确定性算法（价值 = 考试权重 × 掌握缺口，按前置关系拓扑排序） | 可解释、可复现；模型只写标题和说明文字 |
| 资料理解走"逐页规范文本 → 知识点 → 归并建图 → 真题映射 → 考情统计" | 这是"自动分析"与"跟上考题趋势"的全部地基 |
| 前端改为 Vite 单页应用，由 Python 进程直接托管 | 现有 Next.js 只是薄壳（约 98% 是纯客户端代码）；改后一个进程、一个端口、运行时不需要 Node |
| 零密码默认（密钥仍然加密，数据密钥放操作系统凭据库），主密码变为可选 | 学生不该在学习软件第一屏面对"保险箱" |
| 产品代码里没有 Mock；无密钥时提供"示例课回放" | 根除"为通过 Mock 验收而写死逻辑"的土壤 |
| 默认老师形象先用仓库已有、许可清晰的 3 个示例 VRM，并把"导入你自己的 VRM"做成一等功能 | 用代码从零拼不出好看的模型；好看的模型要从 VRoid Studio 的专业部件出发 |
| 6 位立绘老师的 3D 模型走并行的"角色制作支线"：代理操作 VRoid Studio 出底模，所有者挑选，代码做后处理 | VRoid Studio 没有脚本接口，只能点界面（慢、偏脆），所以只让代理做非它不可的一段；先做 1 个当试验再决定是否批量（见 `spec/character-pipeline.md`） |
| 学生随时可以"看答案"，之后必须跟一道同类题 | 只问不答的辅导产品会被学生弃用（有两年跟踪研究的教训）；引导是默认，不是牢笼 |

## 6. 范围

**做（v1.0）**：导入（PDF/PPTX/DOCX/图片/Markdown/文本，含扫描件的视觉转写）→ 课程地图与考情 → 访谈与诊断 → 个性化计划 → 语音 + 白板 + 3D 老师的一对一课堂 → 复习、错题本、练习与模考 → 角色与讲课风格 → 零密码一键启动、示例课、中文界面（结构上预留英文）。

**不做（v1.0 之前不得开工）**：手机壳与局域网配对；多用户/云同步/账号；Live2D/Spine；成人关系模式；服务端视频数字人；WebRTC；自动联网抓取考纲考情（留作 v1.x，需单独设计可信度）；用代码从零拼 3D 角色形体（官方角色只走角色制作支线）；产品内的"捏人"功能；社区角色市场；桌面安装包（Tauri）。

## 7. 里程碑总览

顺序即流水线顺序：**先让它真的会教（文字），再让它开口，再让它"在场"**。每个里程碑都以"一个真实学生能做成一件事"为门，而不是页面数量。

| 里程碑 | 一句话目标 | 结束时所有者能亲手验证的事 |
| --- | --- | --- |
| **M0 止血与地基** | 保住现有成果、清掉死代码、换掉约定 | 工作区已提交快照；仓库瘦身；新 `AGENTS.md` 生效 |
| **M1 新外壳与模型网关** | 一条命令启动、零密码、连上真实模型 | 双击启动 → 选预设粘贴 Key → 页面上与模型流式对话、识别一张图 |
| **M2 资料理解** | 文件进来，课程地图和考情出去 | 拖入自己的一章教材 + 两套真题 → 得到知识点地图、每个知识点的出处与考频 |
| **M3 认识学生与计划** | 访谈 + 诊断 + 个性化计划 | 做完访谈和诊断 → 得到带理由、排到考试日的课表 |
| **M4 教学引擎（文字课堂）** | 真正的一对一课：讲、问、提示、换讲法、回补、判分 | 用文字上完一节 25 分钟的课，连续三次"没听懂"得到三种讲法，答错走提示阶梯 |
| **M5 开口说话** | 分句流式语音、同步时间线、可打断、能听懂你说话 | 戴耳机全程语音上课；一开口老师就停 |
| **M6 老师"在场"** | 自然待机、口型、眼神、手势、指向白板；角色选择与 VRM 导入 | 老师看起来像在讲课而不是 T 字站桩；能换成自己导入的 VRM |
| **M7 学习闭环** | 复习、错题本、练习与模考、进度与重排 | 第二天回来先复习再继续；计划随表现调整 |
| **M8 首次体验与发布** | 引导、示例课、文档、打包、清理 | 另一台干净的 Windows 电脑，按 README 10 分钟内上到第一节课 |

详细任务、验收门与停止点见 `MILESTONES.md`。

另有一条**与主线并行的支线 C（角色制作）**：为 6 位立绘老师做 3D 模型，M0 之后随时可以开始，不阻塞任何里程碑；做出来并通过所有者验收的模型在 M6 接入，没做出来就继续用立绘老师和 3 个 3D 示例角色。

## 8. 质量机制：三层验收与诚实进度

**三层验收（缺一层就不能写"完成"）**

1. **不变量测试（自动、每次提交）**：策略表、解析器、公式、迁移、隔离、密钥不外泄等。断言行为与不变量，不断言常量、哈希、文案或截图。
2. **真实模型评测（有密钥时运行，结果入 `PROGRESS.md`）**：对仓库自带的原创示例课程跑分析流水线；用五种"模拟学生"人设各上完一节课，检查不变量并按评分表打分。没有密钥时，该层状态写"未验证"，里程碑只能标"代码完成"。
3. **所有者实测（每个里程碑的停止点）**：按 `MILESTONES.md` 的清单，用所有者自己的真实资料走一遍。

**状态用语（`PROGRESS.md` 只允许这四种）**：`进行中` / `代码完成（自动化通过）` / `真实模型实测通过` / `所有者验收通过`。

**防空壳硬规则（完整版在 `AGENTS.new.md`；机器可查的部分由本地门里的 `scripts/check_no_fakes.py` 检查）**

- 产品代码（后端、前端、共享包、提示词模板）中不得出现针对具体学科/主题的分支或写死的教学内容（题目、讲解、反馈、卡片）；示例课程与留出课程的主题词不得出现在产品代码里。
- 测试替身只允许存在于测试目录；产品代码不得包含 `mock`/`fake` 供应商、"演示模式"分支或任何切换假实现的开关。
- 面向学生的教学文字只能来自：模型输出、用户资料、内容包（`content/`）。界面文案放在文案文件里，只承担界面功能。
- 课堂上模型不出题、不编例题、不解题；学生不回应不产生任何证据。
- 任何"降级"都必须可见（提示用户当前缺什么能力），不得静默替换为假结果。
- 汇报先写"未完成/未验证/已知问题"，再写完成项；测试数量不是证据。

## 9. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 便宜模型数学/事实出错，教错东西 | 先解后教的独立复核；优先使用资料自带例题与真题官方答案；有争议的题不判分；讲解限定在资料与教案范围内；推荐模型清单按评测结果给出 |
| 课堂延迟破坏"对话感" | 分句流式语音；控件作答不走理解模型；可预测时预生成下一拍；预设里关闭思考模式；首句优先 |
| 分析一本书太贵或太慢 | 开始前给出 token 预估并确认；按内容哈希缓存；可断点续跑；先分析用户选择的章节 |
| 形象质量依赖人工资产 | 默认使用已有示例 VRM；所有者用 VRoid Studio 制作专属角色（`HUMAN-TASKS.md`）；VRM 导入做成一等功能；2D 立绘作为降级 |
| 重塑范围大、代理跑偏 | 里程碑门 + 停止点；M0–M3 期间产品不能用于学习是预期的（旧版保存在标签 `pre-rebuild-20261116`），M4 起每个里程碑结束都是可用的产品；规格先行；范围外事项一律进 `DECISIONS.md` 待议 |
| 再次出现"看起来完成" | §8 的三层验收与硬规则；评测防自证（金标先提交、留出课程、独立评分模型，见 `MILESTONES.md`）；所有者实测是唯一的最终门 |
| 老用户数据 | 表不改名、迁移向前兼容；旧对话只读保留并可导出；旧主密码保险箱提供一次性迁移 |
| 未成年人使用 | 移除成人模式；系统层安全规则；角色卡不能覆盖系统层 |

## 10. 竞品与定位

完整结论与可复用项目清单见 `KICKOFF.md` §2（M0 时抄入 `DECISIONS.md`）。要点（2026-11-16 调研）：

- **已是通用能力**："文档 → 幻灯片/讲解/测验"（OpenMAIC，4 万+ star，MIT；但它是**预生成的固定课**，不随学生表现改变）；资料问答与闪卡（NotebookLM 及其开源仿品）；掌握度闸门与间隔复习（DeepTutor，近 6 万 star，Apache-2.0；以文字对话为主）；VRM 角色的渲染与口型（AIRI、ChatVRM）。
- **本项目要占住的位置**：逐拍生成、可随时打断的一对一授课，且学习者模型真的改变下一句讲什么；基于学生自己的教材与真题的考情驱动计划；按错因换讲法、不限次数的重教；一个 Python 进程即可运行、没有 GPU 也能用、国内模型开箱即连；一位长期记得你的固定老师。
- **清醒认识**：3D 形象不是护城河。护城河是这条回路的质量——响应延迟、板书内容的正确性、学习者模型是否真的改变了教学。这三项做不好，产品只是一个更慢的同类项目。
