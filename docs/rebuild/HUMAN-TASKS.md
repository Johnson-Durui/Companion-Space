## A. 开工前（M0 之前，10 分钟）

1. **工作位置与 git 写权限**：Codex 在 `E:\Codex\Projects\虚拟形象\Companion-Space-v2` 里工作。这个目录是 git 的"链接工作树"，它的版本库数据实际存放在 `E:\Codex\Projects\虚拟形象\Companion-Space\.git`。所以**启动 Codex 时必须允许它写入那个 `.git` 目录**（把它加为可写目录，或使用等效的权限设置），否则 M0 第 2 步的提交会失败。除了 git 自己写入的版本数据，Codex 不会碰旧检出里的任何文件。
2. **重塑前的状态已经存好了**（2026-11-17）：你之前 v2 重构的全部未提交改动已做成快照提交 `c72370f`，打了本地标签 `pre-rebuild-20261116`；Codex 的工作分支 `rebuild/tutor` 从它切出。这些都只在本机，**没有推送**。任何时候想回到重塑前的样子，都可以从这个标签取回。开工前请不要在这个目录里再做别的 git 操作。提交的作者是这个仓库现有的 git 配置（名字 `Codex`、本地占位邮箱）；推送到 GitHub 之前如果想换成你自己的身份，先改 git 配置。
3. **确认"下线不删除"的处理**：以下内容会被移到 `assets-archive/`（不删除），不再作为产品默认内容——
   - 6 个脚本生成的 3D 模型（Mira/Kite/Cael/Lyra/Nova/Echo 的 `.vrm`）。它们是用圆柱、球体等基础几何体拼出来的，放在课堂里的观感会拖累整个产品；**对应的 6 张 2D 立绘很好，会保留并作为"立绘老师"**。
   - 4 个脚本生成的动作文件、Mori/Yuzu 精灵图。
   如果你不同意其中任何一项，开工前告诉 Codex。
4. **知悉一个许可风险**：仓库里带着 `Seed-san.vrm`。它在 VRM 规范仓库里标注为可再分发，但它的作者 VirtualCast 自己公布的条款对"分发未修改的模型数据"有限制，两处说法存在冲突。保守起见，新版本不再随仓库分发它；公开仓库历史里的文件要不要处理（例如发一个移除提交并在 README 说明），由你决定。

## B. M1 之前：准备评测用的模型密钥（15 分钟，可以零成本）

在仓库根目录新建文件 `.env.eval`（已被忽略，不会提交），内容形如：

```
EVAL_BASE_URL=https://open.bigmodel.cn/api/paas/v4
EVAL_API_KEY=你的Key
EVAL_MODEL_LIVE=用于课堂的快模型
EVAL_MODEL_ANALYSIS=用于分析和备课的强模型
EVAL_MODEL_VISION=能看图的模型
EVAL_EXTRA_BODY_LIVE={"thinking":{"type":"disabled"}}
EVAL_EXTRA_BODY_ANALYSIS={}

# 可选：第二家服务（例如硅基流动，提供免费的嵌入与语音识别）
EVAL2_BASE_URL=https://api.siliconflow.cn/v1
EVAL2_API_KEY=第二个Key
EVAL_MODEL_EMBEDDING=嵌入模型名@2
EVAL_MODEL_STT=语音识别模型名@2

# 强烈建议：一个"评分用"的模型，必须和上面被评的模型不是同一个（不同厂商或不同代）
EVAL_MODEL_JUDGE=评分模型名（走第二家就加 @2）
```

- 零成本组合（2026-11 调研）：智谱 BigModel 的免费模型（对话与视觉）+ 硅基流动的免费嵌入/语音识别/OCR（需实名）。更稳更快：DeepSeek（一节 30 分钟的课约几毛钱）。具体模型名以各家官网当天为准——`spec/llm-gateway.md` 里有一张调研快照表。
- 没有这个文件，Codex 仍然可以写代码和跑自动化测试，但所有"真实模型评测"都会写成"未验证"，你也就无法确认它教得对不对。**这是整个重塑里对你最重要的一件事。**
- 没有独立的评分模型时，质量分只能算"自评"，不计入达标。

## C. M2 起：每个里程碑的实测（每次 15–30 分钟）

`MILESTONES.md` 每个里程碑末尾都有"所有者验收清单"。请用**你自己真实在学或学过的一门课**来测（一章教材 + 两三套真题，最好有一份是扫描件或手机拍的照片）——你对内容熟，才看得出它讲得对不对、重点抓得准不准。这些资料只在你的电脑上，不要提交进仓库。

验收不通过就直接告诉 Codex 哪一条不行、现象是什么；**不要因为测试全绿、评测达标就放行**——之前的版本正是在"测试全绿"的情况下变成空壳的。你的亲手实测是唯一的最终门。

## D. M6 之前：老师的形象与声音（核心体验，建议尽早开始，可与开发并行）

**现实情况**：好看的 3D 角色靠代码从零做不出来，起点必须是 VRoid Studio 这类工具里的专业部件。VRoid Studio 没有脚本接口，所以有两种做法，流程都写在 `spec/character-pipeline.md` 和 `MILESTONES.md` 的"支线 C"里：

**做法一（默认）：让 Codex 操作 VRoid Studio，你来挑**

你需要做的：
1. 安装 **VRoid Studio**（免费，有简体中文界面；官网或 Steam）。**第一次启动由你本人完成**：它的使用条款、登录提示都由你处理，确认能直接进入主界面。（我在这台电脑的常见安装位置没有找到它。）
2. 在 Codex 的设置里安装**桌面操作（Computer Use）插件**。它在前台运行：Codex 操作期间你不能同时用这台电脑，最好挑你不用电脑的时段。
3. 新建 `assets-src/characters/author.json`，写上模型里要署的作者名、是否要求署名、允许的商用范围（这些会写进每个模型文件，公开后别人看得到）。
4. 每个角色有两次需要你出场：确认设计单并**在 2–3 个候选里挑一个**；最后**验收**（清单在 `character-pipeline.md` §7）。标准只有一条硬的：整体观感不低于仓库自带的 3 个 3D 示例角色，达不到就不用，继续用立绘。
5. **先只做 1 个角色当试验**。Codex 会报告它花了多久、点错多少次、成品和立绘差多少。你再决定：其余 5 个继续让它做 / 界面部分你自己来 / 暂缓。
6. 发布前对照 VRoid 当时的使用条件原文再核对一次许可（基于预设做的模型可以随仓库分发，但**不能标成 CC0 或 Apache**、不能收费分发）。

要有心理预期：代理靠截图认界面，慢，偶尔点错；选预设和配色它能做好，独特的服装设计（比如星象长袍）只能做到"像这个类型"。

**做法二（兜底）：界面部分你自己来**

照着 Codex 写好的设计单在 VRoid Studio 里手调，熟悉后 1–2 小时一个；导出设置见 `character-pipeline.md` §5.4。导出后的检查、压缩、预览与安装仍由 Codex 用代码完成。

无论哪种做法：在模型做出来之前，产品自带 3 个许可清晰的 3D 示例角色和 6 位立绘老师，主线开发不受影响。

**声音与人设**

7. **声音**：在 M5 的语音设置里给每个角色挑一个音色并试听定稿。想要更"二次元"的声线，可以在本机跑 GPT-SoVITS（你的 RTX 5060 8 GB 足够），产品会提供对接它的适配器——但音色模型的来源与授权需要你自己把关，仓库里不会分发任何音色。
8. **默认老师的人设**：M1 会根据现有角色设定起草 `content/characters/*.json`（名字、说话特点、口头禅、默认讲课风格）。请过目并改成你想要的样子——这是你的角色。
