# 规格 · 角色制作支线（VRoid Studio 出底模 + 代码后处理）

> 这是一条**与主线并行的支线**：为 6 位立绘老师（澄羽 Mira、曜柚 Kite、凛序 Cael、弦灯 Lyra、星澜 Nova、沐音 Echo）做出好看的 3D 模型。它不阻塞任何主线里程碑；做出来之前，产品使用 6 位立绘老师和 3 个 3D 示例角色。
> 一句话：**代理在 VRoid Studio 里点界面出底模，所有者挑选定稿，剩下的配色、贴图、压缩、检查全部交给代码。**
> 为什么这样分：VRoid Studio 没有脚本接口、命令行或批量生成功能，代理只能像人一样看屏幕点鼠标——慢、偶尔点错，所以只让它做"非它不可"的那一小段；而改导出的 VRM 文件是纯代码，可重复、可测试，是代理最拿手的部分。
> 旧版的教训（6 个用圆柱和球体拼出的模型）说明：**不要用代码从零造角色的形体**。本支线的起点永远是 VRoid Studio 的专业部件。

## 1. 分工

| 谁 | 做什么 |
| --- | --- |
| 所有者 | 安装并首次启动 VRoid Studio（它的使用条款、登录提示都由你本人处理）；在 Codex 里装好桌面操作（Computer Use）插件；确认每个角色的设计单；在候选里挑一个；决定模型里写入的作者名与使用许可；最终验收 |
| 代理 · 界面操作 | 在 VRoid Studio 里：选部件、调比例与配色、导入贴图、导出 VRM；每一步记录到"角色配方"里 |
| 代理 · 写代码 | 后处理工具（检查、校验、压缩、换贴图、预览图、对比图、安装）；用它们处理每个导出的模型 |

支线会话与主线会话**不同时进行**：桌面操作在前台运行，会占用整台电脑；两者也都往同一个分支提交。运行界面操作期间，所有者不要使用这台电脑。

## 2. 边界与红线

**允许**
- 操作 VRoid Studio 的界面；读写本支线的工作目录；用代码修改 VRoid Studio 导出的 VRM 文件。
- 用代码生成或修改**贴图**（配色、渐变、纹样、徽记）。

**禁止**
- 用代码从零拼出角色的网格，或用任何"图片/文字生成 3D"的服务产出正式角色（未经所有者批准）。
- 在 VRoid Studio 里登录账号、购买、订阅、上传到 VRoid Hub、点击任何广告或商店入口；代所有者接受条款。遇到登录墙、付费提示、系统弹窗（权限、杀毒、更新）一律**停下汇报**。
- 使用来源或许可不明的第三方部件、贴图、BOOTH 物品。
- 操作 VRoid Studio 及其文件对话框之外的任何程序；修改系统设置；访问工作目录之外的文件。
- 把这条流水线做进产品（产品不得提供基于 VRoid 预设数据的"捏人/导出模型"功能——VRoid 的使用条件禁止以此提供角色创建服务）。

**许可**（发布前由所有者对照 VRoid 当前的使用条件原文再核对一次：`https://vroid.com/en/studio/guidelines` 与预设数据的使用条件页）
- 基于 VRoid 预设制作的模型可以随仓库分发，但**不能标成 CC0 或 Apache-2.0**、不能收费分发、不能暗示 pixiv 认可。
- 每个模型在 `assets/avatars/LICENSES.md` 登记：角色名、"使用 VRoid Studio <版本> 基于 pixiv 提供的预设数据制作，贴图由项目所有者制作"、使用条件链接、"非 CC0，不适用 Apache-2.0"。
- 导出时写入的许可字段必须让应用的许可单测通过（`allowRedistribution` 为真）；其余字段（商用范围、是否要求署名）由所有者决定。

    cand-1/ … cand-3/                每个候选的三张截图 + recipe.json
    textures/src/  textures/out/     导出的底图与模板 / 代码生成的新贴图
    export/<角色id>.vrm               VRoid Studio 导出的原始文件
    review/                          预览图与"立绘 vs 3D"对比图
packages/character-tools/            后处理工具（Node，开发用，不属于产品）
assets/avatars/models/<角色id>.vrm    定稿模型（提交）
assets/avatars/previews/<角色id>.webp 定稿预览图（提交）

`.vroid` 工程文件与中间候选不进仓库；所有者应自行备份 `assets-src/characters/`。

## 4. 流程（每个角色）

| 步骤 | 谁 | 内容 | 产物 |
| --- | --- | --- | --- |
| P0 准备（一次） | 所有者 | 装好 VRoid Studio 并确认能直接进入主界面；装好 Codex 的桌面操作插件；填 `author.json` | — |
| P1 设计单 | 代理 → 所有者确认 | 看立绘（`assets/avatars/portraits/<id>.png`）写出设计单：性别呈现、发色/发型轮廓/长度、瞳色与眼型、肤色、服装类型与配色、配饰、气质；标出"必须像"的 3 点和"可以近似"的部分 | `brief.md` |
| P2 候选 | 代理 · 界面 | 每个角色最多 3 个候选，每个限时 20 分钟：选脸型/发型/体型/服装预设，定主要配色；各截 3 张图（正面半身、四分之三侧半身、全身）；保存工程；记录配方 | `cand-n.vroid`、截图、`recipe.json` |
| P3 挑选 | **所有者（停止点）** | 看对比图选一个，或提出修改意见 | — |
| P4 精修 | 代理 · 界面 | 按设计单调脸部与体型数值、细化配色、加配饰；在表情预览里逐个看喜怒哀乐与口型有没有穿模或崩坏；在拍摄/姿势预览里看肩、腋下、裙摆有没有穿模 | 更新工程与配方 |
| P5 贴图（可选，第二轮再做） | 代理 · 代码 + 界面 | 从 VRoid 导出某个部件的底图与模板 → 代码生成新贴图（瞳孔纹理、服装纹样、发色渐变）→ 在 VRoid 里作为新图层导入 | `textures/out/*.png` |
| P6 导出 | 代理 · 界面 | 按 §5.4 的设置导出 VRM 1.0，写入作者与许可 | `export/<id>.vrm` |
| P7 后处理 | 代理 · 代码 | `inspect → validate → optimize → preview → sheet`（§6） | 报告、预览图、对比图 |
| P8 验收与安装 | **所有者（停止点）** → 代理 | 所有者按 §7 清单验收；通过后 `install` | 提交到仓库的四样文件 |

**先做一个再做其余**：见 §8 的试验门。

## 5. VRoid Studio 操作手册（给做界面操作的代理）

> VRoid Studio 的界面是自绘的，读不到控件结构，只能靠截图。界面文字随版本和语言变化——**以实际看到的为准**；下面给的是结构与意图，不是坐标。

### 5.1 开始前

1. 让所有者把 VRoid Studio 窗口最大化在主显示器上（建议 1920×1080 或更高），关掉会弹通知的程序。
2. 先读 `assets-src/characters/ui-notes.md`（如果有）。没有的话，花 5 分钟只看不改：逐个点开顶部的几个大类（脸、发型、体型、服装、配饰、外观），截图记下"左侧子类列表、中间预设缩略图、右侧数值与颜色面板、右上角的拍摄与导出按钮"各在哪里，写进 `ui-notes.md`。
3. 确认界面语言并写进记录；之后不要改语言。

### 5.2 操作纪律

- **每个动作之后截图确认效果**，不要连点；发现没生效或点错，先撤销（Ctrl+Z）再重做。
- **数值优先于拖动**：右侧面板的每个滑块旁都有数字框，点进去直接输入数值；颜色用十六进制色值输入，不用色盘拖动。
- 每完成一个大类保存一次（Ctrl+S）；候选之间用"另存为"分开，不要覆盖。
- 每个选定的预设名称、每个输入的数值与色值，都立刻记进 `recipe.json`（结构：`{"face":{"preset":"…","params":{"…":0.35}},"hair":{…},"body":{…},"outfit":{…},"colors":{"hair":"#2a6f7f",…},"accessories":[…],"studio_version":"…","ui_language":"…"}`）。
- 时间盒：单个候选 20 分钟、单个角色的精修 40 分钟；超时就保存现状并在记录里写明卡在哪里。
- 统计并上报：动作总数、点错/撤销次数、耗时。

### 5.3 做一个候选的顺序

1. 新建角色，按设计单选基础体型（女性向/男性向）。
2. **脸**：先选整体脸型预设，再依次看眼睛（瞳孔、高光、眼白）、眉毛、睫毛、鼻、口；只改"必须像"涉及的部分。瞳色用色值。
3. **发型**：分别选前发、后发、侧发（以及呆毛、延长发）里轮廓最接近立绘的预设；设主色与高光色。**不要进入手工画发束的编辑器。**
4. **体型**：身高、头身比、肩宽等只做小幅调整，保持默认比例的协调。
5. **服装**：选类型最接近的上衣/下装/连衣裙/鞋袜预设，调主色与辅色。立绘里的独特设计（纹样、徽记、披风）在这一步只求"类型和配色对"，细节留给 P5。
6. **配饰**：眼镜、发饰等，有接近的就加，没有就不加。
7. 转动视角各截一张图（正面半身、四分之三侧半身、全身），保存工程，补全配方。

### 5.4 导出设置

- 格式 **VRM 1.0**。
- 减面：删除被衣服遮住的透明网格；头发做适度简化。目标三角面 ≤ 4 万。
- 合并材质：材质数 ≤ 8；贴图图集分辨率 2048。
- 骨骼：头发骨骼适度精简，但要保留足够的摆动（导出后用 `inspect` 确认弹簧骨组数 ≥ 1）。
- 元信息：标题 = 角色名；作者、联系方式、商用范围、署名要求取自 `author.json`；**允许再分发与改变**（应用的许可单测要求）；暴力与性表现一律不允许。不要选择任何"上传/分享到 VRoid Hub"的选项。
- 导出到 `assets-src/characters/<id>/export/<id>.vrm`。

### 5.5 点不动怎么办

连续 3 次同一步失败，或界面与手册描述差别很大：保存、截图、写明现象，**停下汇报**。兜底方案是由所有者照着 `brief.md` 与本手册手动完成界面部分（熟悉后约 1–2 小时一个角色），P7 之后的步骤不变。

## 6. 后处理工具 `packages/character-tools`

Node（ESM）命令行工具，根目录加 npm 脚本 `characters`。依赖：`sharp`（图像）、`three` 与 `@pixiv/three-vrm`（预览渲染）、Playwright（无头浏览器截图）。

**关键约束：对 VRM 只做"容器级的精确修改"。** 自己实现一个小的 GLB 读写模块（文件头、JSON 块、二进制块；重建二进制块时处理对齐并更新 `bufferViews` 的偏移与长度），只改需要改的部分，其余字节原样保留。**不要用会丢弃未注册扩展的通用 glTF 库整体读入再写出**——那会把 `VRMC_vrm`、`VRMC_springBone`、`VRMC_materials_mtoon` 等扩展丢掉。每次写出后都用 three-vrm 实际加载一遍作为冒烟。

| 命令 | 作用 |
| --- | --- |
| `inspect <vrm>` | 输出 JSON 报告：VRM 版本、元信息与许可字段、三角面数、材质数、每张贴图的尺寸与字节数、具备的表情与口型、人形骨骼、弹簧骨组数、文件大小 |
| `validate <vrm>` | 逐条给出通过/不通过：VRM 1.0；表情齐全（`aa ih ou ee oh`、`blink`、`happy angry sad relaxed surprised`）且视线可用；必需的人形骨骼齐全；`allowRedistribution` 为真；文件 ≤ 8 MB；三角面 ≤ 4 万；材质 ≤ 8；贴图 ≤ 2048；弹簧骨 ≥ 1 组 |
| `optimize <vrm> -o <out>` | 把超过 2048 的贴图缩到 2048、无损重压缩 PNG；可选 `--low` 另出一份贴图 1024 的低配版 |
| `retexture <vrm> --map <json> -o <out>` | 按映射表替换指定贴图、调整材质颜色参数（可选步骤，用于 P5 之外的微调） |
| `preview <vrm> --out <dir>` | 用独立的 three-vrm 页面离屏渲染：正面半身、四分之三侧半身、全身（手臂自然下垂，不出现 T 字姿势），以及"微笑 / 张嘴 / 闭眼"三张表情图 |
| `sheet --portrait <png> --previews <dir> -o <png>` | 把立绘和 3D 预览拼成一张对比图，供所有者挑选与验收 |
| `install <id> <vrm>` | 复制到 `assets/avatars/models/`，生成 `previews/<id>.webp`，复制配方到 `recipes/`，更新 `LICENSES.md` 与 `content/characters/<id>.json`；**只有 `validate` 全部通过才允许执行** |

测试（改动本包时运行，不进主线的默认门）：GLB 读写往返（不修改时逐字节一致）；替换一张贴图后其余 `bufferViews` 内容不变且能被 three-vrm 加载；`validate` 的每条规则各有通过与不通过的用例；用仓库里的 3 个示例 VRM（含 VRM 0.x 与 1.0）做夹具。

## 7. 验收

**自动检查**：`validate` 全部通过；预览渲染成功；`assets/avatars/` 的许可单测通过。

**所有者清单**（对着对比图，再在应用里实际加载看一眼）
- [ ] 一眼能认出是这个角色：发色、发型轮廓、瞳色这三样对。
- [ ] 服装的类型和配色对；细节可以近似。
- [ ] 微笑、张嘴、闭眼都自然，没有破面或穿模。
- [ ] 手臂自然下垂时，肩、腋下、衣摆没有明显穿模。
- [ ] 半身取景（课堂里的样子）好看；头发有自然的摆动。
- [ ] 整体观感不低于仓库自带的 3 个 3D 示例角色。达不到这一条就**不要安装**——宁可继续用立绘。

## 8. 试验门（先只做 1 个角色）

在做全部 6 个之前，先选 1 个角色（建议选设计最简单的）完整走一遍 P1–P8，并报告：

| 记录项 | 说明 |
| --- | --- |
| 界面操作耗时、动作总数、点错与撤销次数 | 评估这条路是否可持续 |
| 对比图 | 立绘 vs 3 个候选、立绘 vs 定稿 |
| 卡住的地方 | 哪些界面点不准、哪些设计做不出来 |
| 后处理结果 | `validate` 报告、文件大小、面数 |

所有者据此三选一：**继续由代理做其余 5 个** / **界面部分改由所有者手动做，代理只做后处理** / **暂缓，继续用立绘老师**。没有这个决定，不得批量制作。

## 9. 与主线的衔接

- **前置**：主线 M0 已完成（仓库已清理、立绘已在 `assets/avatars/portraits/`、新约定已生效）。之后任何时候都可以开始，不必等其他里程碑。
- **M1 之前**完成的模型：先放在 `assets/avatars/models/` 并登记许可；角色内容包里的 `appearance` 等 M1 的角色结构落地后再切换。
- **M6**：把已验收的模型接成对应老师的 3D 形象；为它们离屏渲染 2D 回退用的分层贴图；没有验收通过的角色继续用立绘。应用里"导入你自己的 VRM"的功能与本支线无关，照常做。
- 进度记在 `docs/rebuild/PROGRESS.md` 的"角色支线"小节，状态用语与主线相同；所有者验收是唯一的完成标准。
