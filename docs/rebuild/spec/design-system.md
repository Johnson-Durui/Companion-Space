# 设计系统规格（U 阶段）

> 版本：2026-11-21（已合入一轮三路对抗评审的意见）　|　适用：`rebuild/tutor` 的体验重塑阶段（U0–U7）
> 本文件决定**视觉与组件怎么落地**。界面结构与动线见 `spec/experience-design.md`；做什么、何时做见 `TASK-UX-UPGRADE.md`。
> 文中的版本号、许可、浏览器支持情况是 2026-11-21 的调研快照：**引入或升级任何依赖前先查官方文档与许可文件核对**，结论写入 `DECISIONS.md`。数值（颜色、字号、时长）是起点，所有者看过实物后可以调，但调整必须改 token，不得在组件里写死。

## 0. 现状与目标

现状（2026-11-21 审计）：token 只有 15 个颜色、3 个圆角、2 个阴影；token 之外有 63 个硬编码颜色、23 种字号、31 种像素间距、8 种动效时长；可复用组件只有 `Loading / Problem / ErrorBoundary`；Tailwind v4 只被当作样式重置；声明的三款字体从未加载；没有图标集；`--surface-soft`、`--panel` 两个变量从未定义（访谈、摸底、计划的卡片因此没有背景）。

目标：**一致性由结构保证，而不是靠每页自觉。** 颜色、字号、间距、圆角、阴影、动效只从 token 取；交互控件只从组件库取；页面只做组合。

## 1. 设计语言：书桌与课堂

| | **书桌模式**（日常页面） | **课堂模式**（课堂、示例课、回放） |
| --- | --- | --- |
| 关键词 | 干净、温和、有呼吸感 | 沉浸、专注、老师最亮 |
| 底色 | 暖调的浅灰白 | 接近黑的中性深色 |
| 主角 | 内容卡片与一个主按钮 | 老师视频与白板纸面 |
| 强调色 | 取自当前老师的主题色 | 同一主题色的浅亮版本（光晕、高亮） |
| 控件 | 实心主按钮 + 描边次按钮 | 悬浮在深色上的圆形图标按钮 |

保留的资产：白板的**纸面质感**（暖白底、深墨字）、克制的色彩、已有的白板入场与书写动效、视频框的分层淡入。放弃的做法：宋体标题、发丝线分隔的"出版物"版式、把同一种淡绿用于一切状态、写死的深青色舞台渐变。

三条总原则：

1. **老师是画面里最鲜艳的东西。** 界面本身低饱和；颜色用来指路（主按钮、当前位置、状态），不用来装饰。
2. **层次靠明度与留白，不靠线条。** 卡片用轻阴影或底色差区分，尽量不画边框；同一屏最多三级层次（页 → 卡 → 浮层）。
3. **一个强调色。** 每屏只有一个实心强调色按钮；状态色（对、错、警告、信息）只用于状态。

这组取值是**起点**：对比度已逐项核过；六位老师两两之间在感知色彩空间里的距离都不小于 0.10（肉眼能分开）。观感由所有者在 U1 的组件陈列页上确认，可以调。

规则：

- `--on-accent` 一律为白色；任何主题必须满足：白字对 `--accent` ≥ 4.5:1、`--accent-strong` 对 `--accent-soft` ≥ 4.5:1、`--accent-on-dark` 对舞台面板 ≥ 4.5:1。**为这三条写单元测试**，覆盖全部八组。
- 再加一条单测：六位内置老师的 `--accent` 两两之间的 OKLab 距离 ≥ 0.07（目的只是"换了老师看得出颜色变了"，阈值可在 `DECISIONS.md` 里调整）。
- **主题色与状态色可能相近**（竹青接近"成功"的绿，品牌青也是）。所以规定：**"选中"用强调色描边加选中标记，不用强调色实底；"正确 / 错误"用状态色浅底加图标**。任何主题下，选中与判定都靠"描边 对 底色加图标"区分，不靠色相；实心强调色只用于主按钮。
- 自定义老师没有主题时用默认品牌青；在"调整人设"里可以从上表八组里选，不提供自由取色器。
- 切换老师时颜色变化不做过渡动画。

### 2.5 字体与字阶

**字体栈**

```css
--font-sans: "Geist Variable", "Noto Sans SC Variable", "PingFang SC", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif;
--font-mono: ui-monospace, "Cascadia Mono", Consolas, "SF Mono", monospace;
```

- 西文与数字用 **Geist**（可变字体，SIL OFL 1.1，自托管约 80–160 KB）；中文用 **Noto Sans SC**（思源黑体，可变字体，SIL OFL 1.1，按 unicode-range 切成约 100 片、合计约 4.5 MB，浏览器只取用到的切片）。两者都通过 fontsource 的包自托管，**不用任何 CDN**（应用只在本机运行，必须离线可用）。
- 为什么打包：所有者的电脑上恰好装了思源字体，所以现在的界面在他那里看着正常；没装的 Windows 电脑上，标题会退回系统宋体、正文是微软雅黑，而微软雅黑只有常规与粗体两档，声明的 650 / 750 字重并不存在。打包之后各台电脑显示一致，并且有真正的 500 / 600 字重。
- **不再使用衬线标题。**
- **由所有者在 U1 验收时二选一**（默认决定 D1）：组件陈列页提供"打包字体 / 系统字体"切换（只切 `--font-sans`），并各出一组 14px 正文、20px 标题、课堂字幕的对比截图；所有者在自己平时用的显示器上看哪个更清楚，结果记入 `DECISIONS.md`。调研给出的保守建议是系统字体（零体积、屏幕微调最好）；打包的好处是字重齐全、各电脑一致。
- 若最终选系统字体：字重只用 400 与 700，`text-title`、`text-headline` 改用 700，按钮与标签用 400；其余不变。
- 加载方式：**不手写一百多条规则**。用一个随仓库提交的小脚本，从字体包自带的样式文件生成 `apps/web/src/styles/fonts.css`（只把 `font-display` 改为 `fallback`，`unicode-range` 与文件路径原样保留），并提交生成物；升级字体包时重新生成。应用空闲时调用字体加载接口把全部切片预取一遍，避免课堂字幕出现新字时个别字形闪动。
- 缓存：字体只通过样式里的 `url()` 引用，由构建输出到带哈希的资源目录，后端现有规则已给长期不可变缓存——**不改后端，不放进 `public/`**（那里的文件没有哈希，会被当作不缓存）。
- **许可（这是所有者已批准的许可决定）**：两款字体属于 `AGENTS.md`"素材与许可"里的"字体"，不属于工作纪律里代码依赖的许可名单。SIL OFL 1.1 允许随软件再分发与切片，但分发时必须附带许可全文。落地要求：① 两个字体包只进 `apps/web` 的开发依赖并锁定精确版本；② 两份许可全文放到 `assets/fonts/LICENSES/`，随便携包分发；③ `assets/THIRD_PARTY_NOTICES.md` 新增"字体"小节，逐款登记名称、版本、版权方、许可、来源包；④ `DECISIONS.md` 记一条"字体采用 OFL-1.1，按素材许可处理，可逆"。**小米 MiSans、华为 HarmonyOS Sans 是专有许可，不得放进仓库。**
- 公式继续用 KaTeX 自带字体。

**字阶（只有这六档，外加白板与字幕两个专用档）**

| token | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| `text-caption` | 12 / 18 | 400、500 | 徽标、角标、次要说明 |
| `text-ui` | 14 / 22 | 400、500 | 控件、列表、表单、紧凑界面的正文 |
| `text-body` | 16 / 26 | 400 | 阅读型正文、输入框文字 |
| `text-title` | 20 / 28 | 600 | 卡片标题、分区标题 |
| `text-headline` | 28 / 36 | 600 | 页面标题（每页一个） |
| `text-display` | 40 / 48 | 700 | 老师名字、首屏大标题（少用） |
| `text-board` | 17 / 30 | 400 | 白板正文（行宽 ≤ 约 40 个汉字） |
| `text-caption-video` | 15–18（随视频框宽度）/ 1.5 倍 | 500 | 视频字幕 |

规则：字重只用 400 / 500 / 600，`text-display` 可用 700；不用小于 400 的字重；悬停不改字重；会跳动或需要纵向对齐的数字（计时、分数、进度）用 `tabular-nums`；省略号用"…"；长文本左对齐。

### 2.6 间距、圆角、阴影

- **间距**：4px 基数，只用 `4 8 12 16 20 24 32 40 48 64`（即 Tailwind 的整数步进）；组件内部 4–12，组件之间 16–24，区块之间 32–64。卡片内边距只有三档：16 / 24 / 32。
- **圆角**：`--radius-sm 6px`（徽标、小控件）、`--radius-md 10px`（按钮、输入框）、`--radius-lg 16px`（卡片、对话框）、`--radius-xl 24px`（视频框、首屏大卡）、全圆。嵌套时内圆角 ≤ 外圆角。
- **阴影**（两层：环境光 + 直射光）：
  - `--shadow-1: 0 1px 2px rgb(16 24 32 / .06), 0 1px 1px rgb(16 24 32 / .04)`（静置的卡片）
  - `--shadow-2: 0 4px 12px rgb(16 24 32 / .08), 0 2px 4px rgb(16 24 32 / .05)`（悬停、浮层）
  - `--shadow-3: 0 16px 40px rgb(16 24 32 / .16), 0 4px 12px rgb(16 24 32 / .08)`（对话框、toast）
  - 课堂模式下阴影用纯黑、不透明度加倍。
- **尺寸**：控件高度 32 / 40 / 48 三档；可点击目标最小 40×40px，课堂控制坞 44px，麦克风按钮 56px；图标 16 / 20 / 24。

### 2.7 动效 token

```css
--dur-instant: 80ms;   /* 按压 */
--dur-fast: 120ms;     /* 悬停、tooltip、小浮层 */
--dur-base: 200ms;     /* 菜单、选择器、卡片状态 */
--dur-slow: 320ms;     /* 对话框、抽屉、托盘 */
--dur-page: 450ms;     /* 接通过渡等大面积变化，少用 */
--ease-out: cubic-bezier(0.23, 1, 0.32, 1);       /* 进入与退出的默认 */
--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);   /* 屏内移动、变形 */
--ease-sheet: cubic-bezier(0.32, 0.72, 0, 1);     /* 抽屉、底部托盘 */
```

### 2.8 层级与断点

- `z-index`：`--z-sticky 10`、`--z-dock 20`、`--z-overlay 30`、`--z-modal 40`、`--z-toast 50`。组件里不写字面量。
- 断点（全应用统一为 768 / 1100 / 1600，替换现有的 1100 / 900 / 760 / 759 / 640 / 620 六个值）：`< 768px` 手机；`768–1099px` 紧凑；`≥ 1100px` 桌面；`≥ 1600px` 宽屏。课堂内部的密度切换用**容器查询**（按课堂根容器的宽度与高度），不按视口。
- 高度一律用 `dvh`；固定在底部的东西加 `env(safe-area-inset-bottom)`。

## 3. 技术落地

### 3.1 真正用上 Tailwind v4

- token 写在 `apps/web/src/styles/theme.css`：阶梯类（字号、圆角、阴影、时长、缓动、断点）放 `@theme`；语义颜色先在 `:root`、`[data-surface="stage"]`、`[data-surface="paper"]` 里定义原始变量，再用 `@theme inline` 映射成工具类。映射的命名在 U1 一次定好并写进 `DECISIONS.md`（背景、文字、边框各用各的命名空间，例如 `bg-surface-card`、`text-fg-secondary`、`border-line-subtle`、`bg-accent`），之后不再各自发明。这样换模式、换老师只改变量。
- 元素默认样式放 `apps/web/src/styles/base.css`。
- **层叠顺序与旧样式入层（U1 的第一个提交）**：在样式入口最前面声明层序 `@layer theme, base, legacy, components, utilities;`，并把现有的 `tokens.css`（除 `@import "tailwindcss"` 外的全部规则）与各功能目录下的全局样式文件整体包进 `@layer legacy { … }`。原因：不分层的规则优先于任何层内的规则，不这样做的话，旧的 `h1`、`button`、`.button` 规则会压过所有新组件的工具类。**禁止用 `!important` 或提高选择器权重去对抗旧样式**；每个里程碑删掉自己负责页面在 `legacy` 层里的规则，U7 结束时 `legacy` 层为空。
- 组件内部用工具类；**不再新增页面级全局类**。`packages/*` 内不使用工具类（扫描范围不含工作区包），只用普通样式或样式模块并取 token 变量。
- 深色与浅色不依赖系统的明暗偏好：课堂深色由 `data-surface` 决定。全站深色主题不在本阶段范围内。

### 3.2 目录

```text
apps/web/src/
  styles/theme.css        token
  styles/base.css         元素默认与少量全局规则
  ui/                     组件库（每个组件一个文件，带单元测试）
  ui/icons.ts             图标的统一出口
  shell/                  三种外壳、导航、路由级错误边界
  features/…              只做组合，不写一次性样式
packages/avatar-engine/   视频框的样式随包走（现在定义在应用层的 classroom.css 里）
packages/board/           白板样式继续用 CSS Module，但颜色、字号全部取 token，删掉与 token 不一致的回退值
```

### 3.3 旧样式的迁移纪律

1. **U1 先整体换肤**：把旧变量（`--bg`、`--paper`、`--ink`、`--muted`、`--line` 等）改为指向新的语义 token，字体栈换掉——所有旧页面立刻获得新配色与新字体，不出现"半新半旧"。**`--accent`、`--accent-strong`、`--accent-soft` 新旧同名**，不做"指向"，直接由老师主题变量接管；旧的 `--accent-strong` 是近黑色，被当作深色文字或深色底使用的旧规则要逐处改用 `--text-primary` 或核对对比度。
2. 之后每个里程碑把自己负责的页面改成"组件 + 工具类"，并**在同一批提交里删掉对应的旧全局类**；不允许新旧两套长期并存。到 U7 结束时 `tokens.css` 与 `legacy` 层应当已经不存在。
3. 视频框的类名（`tvb-*`）被驱动代码直接操作，改名或调整层序前先读 `packages/avatar-engine` 的驱动与 `apps/web/tests/avatar-runtime.test.ts`。视频框的样式现在定义在应用层的课堂样式文件里、被四处引入；迁移时在形象包的导出表里加样式入口，四处引入改为引这个入口。
4. 现有端到端用例大量用类名定位。**先把用例改为按角色与名称、或 `data-testid` 定位，再改结构**（以 `grep -n "locator(" tests/e2e` 的结果为准，不以任何清单为准）。现有的状态属性 `data-pose`、`data-action`、`data-clip`、`data-state` 是给测试与样式共用的契约，保留；`data-phase` 在 U2 新增。

### 3.4 机器检查（前端单测，随本地门运行）

- 样式表中用到的自定义属性必须有定义（运行时写入的变量列白名单：`--speech-level`、`--tvb-fade-ms`、老师主题变量）。从 U0 起。
- 十六进制颜色只允许出现在主题文件与一份**遗留白名单**里。白名单在 U1 建立，列入当时仍含硬编码颜色的旧文件（旧的 token 文件、课堂样式文件、白板样式模块等）；**只减不增**：每个里程碑重做到的文件同批从白名单移除，新建文件一律不得进入白名单；U7 结束时白名单为空并删除该机制。KaTeX、流程图主题配置列第三方白名单。
- 主题对比度与区分度测试（§2.3）。
- 不出现 `transition: all`；`legacy` 层之外不出现不分层的元素选择器规则；不出现 `!important`（第三方样式列白名单）。

## 7. 动效规范

### 7.1 原则（来源见 §13）

- 只动 `transform` 与 `opacity`；不用 `transition: all`；不动宽高与位置属性（高度展开用网格行或组件库的做法）。
- 一般界面动画 ≤ 300ms，对话框与抽屉 ≤ 500ms；退出不长于进入；不从 `scale(0)` 出现，起始不小于 0.93；浮层从触发点方向展开。
- 进入与退出用 `--ease-out`；屏内移动用 `--ease-in-out`；颜色与悬停用默认缓动；不用 `ease-in`。
- 键盘触发的动作、每天会发生很多次的动作（切换标签页、列表导航）不加动画或只做几乎察觉不到的变化；学生正在读的内容不为了风格而移动。
- 动画可被新的输入打断；快速连续触发的效果用过渡而不是关键帧。
- 不可见时暂停循环动画（包括离屏的老师视频）。

### 7.2 规定动作

| 场景 | 动作 | 时长 / 缓动 |
| --- | --- | --- |
| 按钮按下 | `scale(0.97)` | `--dur-instant` |
| 悬停 | 底色或明度变化 | `--dur-fast` |
| tooltip、小浮层 | 淡入 + 4px 位移 | `--dur-fast` / `--ease-out` |
| 菜单、选择器 | 淡入 + 从 0.96 放大 | `--dur-base` / `--ease-out` |
| 对话框 | 遮罩淡入；面板淡入 + 从 0.96 放大 | `--dur-slow` / `--ease-out` |
| toast | 从边缘滑入；淡出 | `--dur-base` |
| 路由切换 | 交叉淡入淡出（View Transition） | 约 200–250ms；浏览器前进后退时可不播 |
| 列表重排（计划顺延、置顶） | 位置过渡 | `--dur-slow` / `--ease-in-out` |
| 作答托盘 | 从底部滑出 | `--dur-slow` / `--ease-sheet` |
| 选项判定 | 正确：勾画出 + 柔和底色；错误：左右轻晃一次（位移 ≤ 6px） | 300ms 内 |
| 白板新块 | 现有的上移淡入与逐行书写，保留 | 250–400ms |
| 接通课堂 | 舞台由居中移到左列，白板滑入 | `--dur-page` / `--ease-in-out` |
| 麦克风录音 | 外环随音量缩放 | 跟随音量，更新不低于每秒 15 次 |
| 老师说话 | 声波条或边缘柔光随音量变化 | 同上 |

### 7.3 减少动态效果

系统开启"减少动态效果"时：位移与缩放改为淡入淡出，而不是全部关掉；循环动画停止；滚动改为瞬时；老师的循环短片改为静帧或极缓慢的交叉淡化。**不要依赖把所有时长压到近似 0 的全局规则**——它会让等待动画结束事件的逻辑瞬间触发；改为各组件自己声明降级。状态指示（在听、在想、在讲）在降级下仍要有可见变化（例如透明度呼吸），不能冻结。

## 8. 反馈与表单规范

**时序**

| 情况 | 规则 |
| --- | --- |
| 任何点击或按键 | 下一帧就有可见变化（按下态、选中态），不超过 100ms |
| 等待少于 0.4 秒 | 不显示任何加载指示 |
| 加载指示 | 0.4 秒后才出现；一旦出现至少显示 0.4 秒，避免闪烁 |
| 1–10 秒 | 整屏用与最终布局同形的骨架，单个模块用转圈；加载未结束时**绝不**显示"暂无内容" |
| 10 秒以上 | 显示进度或步骤，并允许离开或取消 |
| 学生说完话 | 100ms 内切到"在想"的视觉状态；超过约 1 秒有持续的进行性反馈；超过 3–4 秒出现可取消或可打字的入口 |

**进行中与成功**：提交开始后按钮进入 `pending`（保留原文案 + 转圈、防重复提交）。成功在触发处就近反馈（按钮短暂变为"已保存"或出现对勾），同时可以有 toast；toast 不能是唯一痕迹。确定性高的操作做乐观更新（计划项置顶与顺延、资料类型修改、选老师），失败时回滚并报错。

**禁用**：禁用（条件不满足）用"不可用"光标与降低的对比度，并在旁边用文字说明原因；进行中才用进度光标。不要因为表单没填完就预先禁用提交按钮——允许提交，然后把焦点带到第一个错误。

**确认与撤销**：能撤销的操作直接执行并在 toast 里给"撤销"；不可撤销且后果严重的才用确认对话框，写出对象名称与后果，按钮用动词（"删除课程" / "保留"），确认按钮不是默认焦点。

**表单**：失焦后校验，输入未完成前不报错；错误写在字段旁并说明怎么改；提交时聚焦第一个错误。开关、滑杆、分段控件即时生效；含文本框或下拉的表单显式保存，并在有未保存更改时显示保存条；同一表单不混用两种方式；离开有未保存更改的页面前提醒。密钥输入框可粘贴、可显示/隐藏，保存后只显示掩码。

**错误文案**：发生了什么 + 现在可以怎么做（带按钮）；不责怪学生；不出现"操作失败""无效""非法"；错误码与技术细节放在可展开的"详情"里。

## 9. 声音提示

- 只作为补充，任何提示音都有等价的视觉反馈；设置里有独立开关（默认开）与音量，默认音量明显低于老师的声音。
- 用现有的音频上下文合成，不带音频文件。每个提示音短于约 0.3 秒，主频在 600 Hz–2 kHz 之间，上行音表示积极，下行音表示结束。
- 清单：接通、轮到你了、开始录音、结束录音、答对、答错（柔和，不刺耳）、下课。
- **老师说话时、麦克风正在收音时不播放**（避免干扰语音识别与听感）；同一个提示音 40ms 内去重。浏览器要求用户手势后才能出声，提示音只在课堂开始之后启用。

## 10. 可访问性基线

- 全流程可只用键盘完成；焦点环始终可见、贴合圆角、不被遮挡（2px，强调色，与背景对比 ≥ 3:1）。
- 对话框与抽屉圈定焦点并在关闭后归还；路由切换后更新页面标题、把焦点移到页面标题、滚动回顶。
- 文字对比 ≥ 4.5:1，大字与图形、控件边界 ≥ 3:1；状态不只靠颜色表达。
- 异步结果用 `aria-live` 播报：普通状态 `role="status"`，错误 `role="alert"`；只播报用户感知不到的变化，不每秒播报（练习倒计时改为每分钟与最后 10 秒播报）。
- 只有图标的按钮必须有可访问名；装饰元素对读屏隐藏。
- 字幕默认开启；语音内容都有文字等价物（字幕与对话记录）。
- 自动播放且超过 5 秒的运动内容（老师循环短片）可以关闭为静态立绘。

## 11. 图表组件（手写 SVG，不引入图表库）

| 组件 | 表达 | 数据 |
| --- | --- | --- |
| `MasteryGrid` | 按单元分组的知识点方格；颜色与形状 = 掌握状态；边框或角标 = 考试权重 | 进度接口的知识点列表 |
| `WeightBar` / `MasteryBar` | 两条并排的小横条：考试权重、当前掌握 | 计划项的理由数据、地图 |
| `ScoreBar` | 已保住分值 / 满分，带目标线 | 进度接口 |
| `ScoreRing` | 练习与模考得分 | 练习结果 |
| `StudyCalendar` | 最近 8 周每天有无作答记录 | 进度接口（新增的日期列表） |
| `WeeklyMinutes` | 每周学习时长柱状图 | 进度接口（新增） |

## 12. 一屏的完成定义（评审清单）

反馈

1. 每个可点元素都有悬停、聚焦、按下、禁用四态；按下 100ms 内有可见变化。
2. 短于约 0.4 秒的等待不出指示；指示延迟出现、最短显示；10 秒以上有进度与离开的办法。
3. 整屏加载用同形骨架；加载未结束不显示"暂无内容"。
4. 提交中的按钮保留文案加转圈并防重复提交；成功就近反馈。
5. toast 停留约 5 秒、悬停暂停；带操作的不自动消失。

动效

6. 只有 `transform` 与 `opacity` 在动；时长与缓动全部来自 token。
7. 一般动画 ≤ 300ms，对话框与抽屉 ≤ 500ms；退出不长于进入。
8. 键盘触发与高频操作不加动画；动画可被打断。
9. 减少动态效果时位移改为淡化，循环停止，状态指示仍可辨。

布局与文字

10. 间距、圆角、阴影全部来自 token；嵌套圆角同心。
11. 字号只用六档；字重只用 400 / 500 / 600；长文行宽 ≤ 约 40 个汉字。
12. 会变化的数字用等宽数字；没有布局跳动（图片与视频有固定宽高比，骨架等高）。
13. 可点击目标 ≥ 40px，相邻项之间没有点不到的缝。
14. 每屏只有一个实心强调色按钮。

状态与文案

15. 加载、空、错误、成功四态都做过且可达；每屏都有下一步，没有死路。
16. 错误文案 = 发生了什么 + 怎么办（带按钮），就近显示，不裸露原文与错误码。
17. 破坏性操作优先撤销；否则确认框写明对象与后果，按钮用动词。
18. 没有浏览器原生的确认框、下拉外观、进度条、音频条。
19. 默认界面没有学生词表（体验规格 §6.2）里的禁用词，没有英文残留。

媒体与语音

20. 在听、在想、在讲、等你回答，各有不同的视觉与文字标签，且与真实状态一致。
21. 字幕不遮脸、最多两行、对比足够。
22. 视频片段切换无露底、无黑帧、无尺寸跳变。
23. 提示音可关、短、明显轻于语音、从不作为唯一信号。

可访问性

24. 纯键盘可完成；焦点环可见；对话框圈定并归还焦点；路由切换后更新标题并移动焦点。
25. 文字对比 ≥ 4.5:1，图形与控件边界 ≥ 3:1；老师主题色通过对比度测试。

## 13. 依据（2026-11-21 调研，供核对）

- 响应时间三条界限、骨架屏、进度指示、错误文案、确认对话框、空状态：Nielsen Norman Group 的相关文章。
- 界面细节（按压、加载最短显示、乐观更新、焦点、表单）：Vercel Web Interface Guidelines；Emil Kowalski 与 Rauno Freiberg 关于交互与动效的公开准则（按压缩放 0.97、缓动曲线、时长范围、"高频操作不加动画"）。
- 动效时长与缓动的参照：Material Design 3 的时长与缓动 token。
- 对比度、目标尺寸、焦点、状态消息、运动内容：WCAG 2.2。
- 中文界面字号与行高：Ant Design 字体规范；W3C《中文排版需求》。
- 字幕：BBC Subtitle Guidelines（竖屏行数与位置）、Netflix 简体中文字幕规范（每行约 16 字）。
- 提示音：Microsoft 与 Material 的界面声音指南（短、中高频、轻、非唯一通道）。
- 依赖版本、许可与浏览器支持：npm registry、各库官方文档、web-features 基线数据。
- 参照产品（布局与状态表达）：ClassIn 与 Preply 的课堂布局（白板为主、人像可切换为小窗）、Duolingo 视频通话（接通仪式、角色可见反应、通话后回顾）、Gemini Live 与 ChatGPT 语音（暂停、静音、结束分开；语音与文字是同一条会话）、Photomath（一次一步、标出当前步骤）、Khan Academy（有名字的掌握档位、活动后的升降清单）、Praktika（老师卡片的第一人称问候、思考状态标识）。这些只作为模式参照，不照搬任何产品的视觉。
