# Companion Space 产品交付计划

用户目标：查看逆向资料，丰富虚拟形象项目，形成可交付的成品；上下文接近 90% 时在新窗口续接。

## 现状与范围

以当前工作树为基线，保留所有历史未提交改动。Next.js / React + FastAPI / SQLite，桌面浏览器为主，包含原创 VRM、2D、资料检索、实时共学和复盘。类型检查与前端 lint 初始通过。旧计划和旧发布测试只能作为线索，不能替代本轮证据。

用户已确认参考对象为 Eciyuan 虚拟角色。已核对相关报告、复刻规格、实机补充与截图，迁移记录见 `docs/design/eciyuan-adaptation.md`。不涉及偏振相机任务。

## 完成标准

1. 记录指定逆向资料的来源、证据、可迁移的交互/功能及实现对应；遵循现有许可证边界。
2. 首次使用能理解本地保险箱、演示能力与真实模型的区别，并顺畅进入资料、角色和共学闭环。
3. 核心页面在桌面和窄屏上布局完整，加载、空白、失败、重试及权限状态可理解。
4. Windows 可在无 Bash、无个人固定路径情况下运行验证；使用隔离测试数据，不触碰真实 storage。
5. 提供干净的交付目录/归档、启动说明、功能说明、已验证清单与真实剩余限制；不含密码、运行数据库或构建缓存。
6. 当前工作树的后端测试、前端类型/lint/build、主流程 E2E 和实际截图检查通过。

## 实施顺序

1. 建立基线：API Ruff/pytest；Web typecheck/lint；读取真实 UI 与当前启动路径。
2. 启动可移植化：先写安全边界回归测试，再改 Node bootstrap 与 Windows launcher；测试构建隔离，不清理用户构建或存储。
3. 根据实际页面改善首次体验和共学入口；复用现有 API、组件、素材与设计变量，无新增依赖。新增行为先以用户交互测试约束。
4. 指定逆向资料到位后提炼有证据的增量需求，落实到现有系统，并记录差异。
5. 全量验证，截图审阅，制作可重复生成的交付包及手册。

## 设计说明

- 界面：本地优先的二次元伴学产品，主要任务是和选定伙伴围绕自己的资料开始学习。
- 视觉主张：沿用「星轨书房」暖纸色、深青色和原创伙伴插画；用清晰的学习路线降低首次使用成本。
- 标志元素：从空间到共学再到回顾的路线与书签；避免新增平行导航系统。
- 状态：初始化、解锁、准备就绪、没有资料、正在索引、不可用、可重试、继续上次会话。
- 技术：现有 React/Next.js、CSS Modules/全局语义变量；应用 vercel-react-best-practices 的并行读取、按需加载和副作用清理规则。
- 验证：隔离数据库的实际 API + Playwright，桌面 1440、平板 768、手机 390；不以截图代替持久化验证。
