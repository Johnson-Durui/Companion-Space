## Release Intent

Companion Space v0.1 is the open-source, self-hosted version of the study companion
workspace. The default product name is neutral (`Companion Space`), the default
launch path is Mock, and real providers are opt-in through BYOK.

The v0.1 user loop is:

`Unlock the local vault -> connect a provider or use Mock -> create a study space -> import materials -> create a character -> start a voice or text call -> use the lesson board and step-by-step demo -> review citations and recap -> confirm memory candidates`

The visible companion is a cute or cool anime-style character, not a fixed teacher
persona. Explanation, questioning, diagnosis, and review happen as companion
behaviors within the study flow.

## What v0.1 Includes

- Local single-user deployment on one machine.
- Browser-rendered anime-style characters instead of a fixed teacher persona.
- Study spaces with scoped materials, citations, transcripts, summaries, memory
  candidates, and review items.
- A complete Mock path for a fresh local state with no API key.
- BYOK connection implementations for OpenAI-compatible, Anthropic, Gemini,
  ElevenLabs, and Ollama providers. Real-provider validation remains an external
  manual release gate.
- Mermaid-based lesson boards and step-by-step demo playback.
- Privacy defaults that keep raw audio ephemeral and provider keys encrypted on the
  server side.

## What v0.1 Does Not Include

- Public cloud accounts, multi-user collaboration, or cross-device cloud sync.
- WebRTC, camera processing, or AI-generated 3D avatars.
- Phone/LAN pairing, one-time pairing codes, or trusted-device management; those are
  v0.2 work.
- A full offline model bundle.
- Automatic course generation or knowledge-graph authoring.

The legal-tutor demo pack is optional only. It lives under
`sample_data/demo-packs/law-luze/` and is not auto-imported on startup.

## Setup Paths

### Mock-first path

1. Copy `.env.example` to `.env`.
2. Install the Python and npm dependencies.
3. Start the API and web application.
4. Initialize and unlock the local vault.
5. Use the built-in Mock provider to complete the product loop.

Mock is the supported first-run path for a fresh local state and does not require an
API key.

### BYOK path

1. Initialize and unlock the local vault.
2. Add a provider connection from the Providers screen.
3. Test the connection with the intended endpoint.
4. Bind each required capability to the study space explicitly.
5. Use only the capabilities declared by that provider.

If a provider fails, the application surfaces the provider-specific reason. A
missing voice capability degrades to text instead of silently switching vendors.

## Privacy And Safety

- Owner authorization is required for REST and realtime session access.
- Provider keys remain server-side and are not returned to or stored by the browser.
- Raw audio is ephemeral by default; the 30-minute audio soak found no uplink or
  downlink PCM canary, audio marker, audio file, SQLite/WAL value, or transcript in
  logs after the session.
- Uploaded materials and imported packs are treated as untrusted input.
- Citations come from server retrieval hits rather than model-authored source claims.
- `storage/` is runtime data only and must not be included in a source distribution.

## Verification And Sign-off

Local automation establishes the current release-candidate status. It does not
replace real remote-provider credentials, physical microphone/headset sessions, or
Edge.

The browser PCM injection evidence exercises the client state machine and the
scheduled playback proxy; it does not prove real microphone capture.
