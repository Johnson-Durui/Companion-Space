# Companion Space v0.1 Runbook

## Purpose

Use this runbook to start a fresh local copy, complete the Mock smoke path, connect
optional BYOK providers, and collect release evidence without overstating unrun
manual checks.

Phone/LAN pairing and mobile-browser access are v0.2 features and are not part of
this v0.1 runbook.

## Prerequisites

- Node.js 24 or newer.
- Python 3.13.
- A working clone of this repository.
- Docker Desktop only when using the Compose path.

## Fresh Local Setup

```bash
cp .env.example .env
python3 -m venv .venv
.venv/bin/pip install -r services/api/requirements-dev.txt
npm ci
```

Start the API from the repository root:

```bash
PYTHONPATH=services/api .venv/bin/uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Start the web application in a second terminal:

```bash
npm run dev:web
```

## Mock First-Run Smoke

1. Open the local web application.
2. Initialize the vault with a new master password and unlock it.
3. Confirm the built-in Mock connection declares chat, analysis, embedding, STT,
   and TTS capabilities.
4. Create a blank study space.
5. Paste or upload a supported material and wait for indexing to finish.
6. Create a character and make it the space default.
7. Start a session, submit a question, and confirm the response cites the imported
   material.
8. End the session, wait for the recap, edit it, explicitly confirm a memory
   candidate, and inspect the review queue.

The automated equivalent is:

```bash
npm run test:e2e
```

The default suite skips the long soak. Run the two release-only performance lanes
separately:

```bash
# Headed Chromium; fails when the browser reports SwiftShader/software rendering.
npm run test:e2e:vrm-performance

# Production Next.js server; runs for 30 minutes and writes ignored JSON evidence.
npm run test:e2e:realtime-soak
```

Use `npm run test:e2e:realtime-soak:smoke` only to validate the harness while
developing it. A short smoke is not release evidence and must not replace the
30-minute command.

The release-day result is recorded in
[v0.1 Evidence Log](v0.1-evidence.md).

## Four-State VRMA Verification

Run these commands from the repository root after `npm ci`. They verify that the
bundled `idle`, `listening`, `thinking`, and `speaking` assets still match the
deterministic CC0 generator and load and retarget through the production VRM
libraries against both VRM 0.x and VRM 1.0:

```powershell
node scripts/generate-cc0-vrma.mjs --check
node scripts/verify-cc0-vrma-runtime.mjs
```

The runtime verifier must report four assets across VRM 1.0 and VRM 0.x, five
tracks and zero unresolved bindings for all eight combinations, running actions,
and a non-zero hips quaternion delta.

Validate the files with the same pinned Khronos validator used for release
evidence. This PowerShell sequence installs the validator outside the worktree:

```powershell
$validatorRoot = Join-Path $env:TEMP "companion-space-gltf-validator-2.0.0-dev.3.10"
npm install --prefix $validatorRoot --no-save --ignore-scripts gltf-validator@2.0.0-dev.3.10
$env:NODE_PATH = Join-Path $validatorRoot "node_modules"
try {
    node scripts/validate-cc0-vrma.cjs
} finally {
    Remove-Item Env:NODE_PATH -ErrorAction SilentlyContinue
}
```

Record `PASS` only when all four JSON results show `errors: 0` and `warnings: 0`.
Generator or validator success alone does not prove browser playback; retain the
runtime verifier and isolated Playwright/browser evidence as separate gates.

## Docker Compose

Start the full stack:

```bash
cp .env.example .env
docker compose up --build
```

The public entrypoint is `https://companion.localhost`.

### Windows runtime backup

Create the normal full recovery backup from PowerShell:

```powershell
.\BACKUP-WINDOWS.ps1
```

The script briefly stops only a running API, requires a non-busy `TRUNCATE` checkpoint, snapshots SQLite, copies Vault/material/character files, verifies SHA-256 hashes, publishes a unique backup directory, and restores the API's prior running state. For an online SQLite-only snapshot use `-OnlineDatabaseOnly`; it is not a full application backup. Never treat a retained directory ending in `.partial` as valid evidence or a recovery point.

Run the isolated release smoke:

```bash
./scripts/docker-smoke.sh
```

The smoke is successful only when it reports that Caddy, API, web, health route,
application shell, vault proxy, and WebSocket ticket guard all passed. If Docker
Desktop is updating, requesting privileged-helper setup, or has no daemon socket,
record the result as `WAITING`; do not convert a Compose parse result into a runtime
PASS.

## BYOK Provider Setup

1. Initialize and unlock the local vault.
2. Add the intended provider connection from the Providers screen.
3. Enter its endpoint, model, and secret as required.
4. Test the connection and keep any provider-specific failure visible.
5. Bind capabilities to the current study space explicitly.
6. Verify chat, embedding, STT, or TTS separately; one working capability does not
   prove the others.

OpenAI-compatible providers may use a custom Base URL. Ollama must point to a
running local endpoint. Never mark these manual rows PASS without a real request;
see [v0.1 Manual Matrix](v0.1-manual-matrix.md).

For HTTPX-based providers, each operation resolves and validates the effective
endpoint once, pins TCP connections to that address snapshot, and keeps the
original hostname for TLS certificate verification, SNI, and `Host`. Redirects
and environment proxies are disabled. A DNS or address-policy error is a visible
failure: temporary DNS lookup errors are reported as provider unavailable, while
invalid or blocked targets are provider configuration errors. Do not bypass either
by using an IP URL or disabling certificate verification.

## Release Verification Commands

Run from the repository root:

```bash
.venv/bin/ruff check services/api
PYTHONPATH=services/api .venv/bin/python -m pytest services/api/tests -q
npm run typecheck:web
npm run lint:web
npm run build:web
npm run test:e2e
npm run test:e2e:vrm-performance
npm run test:e2e:realtime-soak
node scripts/generate-cc0-vrma.mjs --check
node scripts/verify-cc0-vrma-runtime.mjs
npm audit --audit-level=high --package-lock-only
.venv/bin/pip install pip-audit
.venv/bin/pip-audit -r services/api/requirements.txt --progress-spinner off
docker compose config --quiet
./scripts/docker-smoke.sh
```

On native Windows, run the shell and line-ending gate with Windows PowerShell 5.1:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\windows-smoke.ps1
```

An existing Windows checkout is not rewritten automatically when `.gitattributes`
is first added. If the smoke names a file with CR bytes, confirm the worktree has
no intentional edits, convert only the reported shell files to LF, and rerun the
smoke. A fresh checkout applies the LF policy automatically; do not weaken or skip
the gate.

The `windows-smoke` GitHub Actions job runs this gate, Ruff, and the full backend
suite on `windows-latest`. Record the hosted run URL, commit, and date before
claiming that hosted Windows CI passed; a local PowerShell result is separate
evidence.

Run `npm run build:web` and `npm run test:e2e` sequentially when using one
worktree. The E2E bootstrap clears `apps/web/.next` before starting its development
server; running it concurrently with `next build` invalidates both results. GitHub
Actions uses isolated jobs, so the CI build and E2E jobs do not share that directory.
The realtime soak script performs its own production build and must likewise run
without another process writing `apps/web/.next`.

Record exact results and all `NOT RUN` or `WAITING` rows in
`docs/release/v0.1-evidence.md`.

## Runtime Data

- `storage/` is runtime state and is ignored by git.
- `.playwright/` is isolated E2E runtime state and is ignored by git.
- Do not distribute populated runtime directories in source releases.
- `backups/` is private runtime state and is ignored by git. Encrypt it before moving it off the trusted host.
- Do not place real provider keys in fixtures, logs, screenshots, or release notes.
- After an audio session, scan runtime storage, SQLite/WAL, and logs for audio files,
  PCM markers/canaries, and transcript text. The release soak performs this scan
  automatically.

## Troubleshooting

| Symptom | Expected response |
| --- | --- |
| Provider request fails | Show and record the provider-specific reason; do not silently switch vendor. |
| Capability is missing | Fall back to text-only behavior when possible and show why voice is unavailable. |
| Material indexing fails | Keep the failed job visible; do not present the material as searchable. |
| VRM fails to load | Keep text conversation available and expose the character-load failure. |
| Docker daemon is unavailable | Finish Docker Desktop setup and rerun `./scripts/docker-smoke.sh`; leave the gate `WAITING` meanwhile. |
| Phone pairing is absent | Expected for v0.1; the trusted-device/LAN flow is v0.2. |
